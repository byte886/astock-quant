## 一、量化基础概念

### 什么是量化交易

- **主观交易**：靠经验、直觉、看盘感受，"这只股基本面不错、情绪好，我感觉要涨"
- **量化交易**：写一套明确无歧义的数字规则，用历史数据回测验证，可程序自动执行
- 量化 ≠ 高频：高频只是量化的一个分支，量化可以是低频（每周选股、每月调仓）
- 量化 ≠ 自动下单：轻量量化可以是程序算出信号、人手动买卖

### 量化的关键特点

1. **规则无歧义**：全部量化成数值，不能写"看起来强势就买"
2. **历史回测**：拿过去多年行情跑规则，看能不能赚钱、最大回撤、胜率
3. **可程序执行**：可选全自动（对接券商接口）或半自动（信号+人工下单）

### 常见被量化对象

- 价格类：均线、波动率、振幅
- 量能类：换手率、成交量变化
- 基本面：PE、PB、营收增速
- 文本信息（AI 做的部分）：新闻、财报、舆情 → 提炼成数字打分（情绪因子）

## 二、开源量化框架对比（待深入验证）

### 候选框架

| 框架 | 开源协议 | GitHub Star | 定位 | A股适配 | 批量回测 | 实盘 |
|---|---|---|---|---|---|---|
| **vn.py (VeighNa)** | MIT | 23k+ | 全链路交易引擎 | ⭐⭐⭐ 原生支持T+1/涨跌停/100股/印花税，内置多家券商柜台 | 一般（事件驱动，单标的强） | ⭐⭐⭐ 可直接实盘自动下单 |
| **QuantDinger** | Apache2.0 | 较新 | AI 量化 + WebUI | ⭐⭐ AkShare行情，A股需扩展 | 一般 | 需二次开发 |
| **qlib (微软)** | MIT | - | AI 因子挖掘 + 批量回测 | ⭐⭐ 需适配A股 | ⭐⭐⭐ 向量化，全市场强 | 不擅长（研究导向） |
| **Hikyuu** | - | - | 多因子 + 批量回测 | ⭐⭐⭐ A股原生 | ⭐⭐⭐ 强 | 一般 |
| **Backtrader** | - | - | 单标的回测 | ⭐ 国外框架，原生不适配 | 差（单标的强，全市场拉胯） | 一般 |

### 关键结论（待验证）

- **vn.py**：口碑最好、A股适配最强、实盘最成熟，但批量回测性能一般（事件驱动架构）
- **qlib / Hikyuu**：擅长全市场批量多因子回测，向量化运算快，但实盘能力弱
- **QuantDinger**：原生内置 LLM 接入层，可直接接入 Grok/豆包，Docker 一键部署，Web 界面，但项目偏新、A股社区案例少
- **Backtrader**：国外框架，单标的回测强，但 A 股不适配、批量回测差，不推荐

### 框架设计目标差异（为什么批量回测能力不同）

1. **多因子、批量全市场选股** → 原生支持大量股票批量回测（qlib/Hikyuu）
2. **实盘交易引擎，回测只是附带** → 批量回测性能一般（vn.py）
3. **低代码 AI 策略生成、WebUI，面向新手** → 批量回测能力弱（QuantDinger）
4. **国外框架** → 单标的回测强，批量全市场拉胯（Backtrader）

## 三、Grok Bot + QuantDinger 调研（待验证）

### Grok Bot（Musk / xAI）

- 定位：AI 助手，可做舆情分析、新闻解读
- 特点：实时信息接入（X 平台），适合做市场情绪/新闻因子
- 接入：通过 API 调用，不消耗本地硬件

### QuantDinger（量化丁格）

- Apache2.0 开源，私有化部署，策略/数据本地保存
- 原生内置 LLM 接入层，可直接接入 Grok，自然语言生成 A 股策略代码
- Docker 一键部署，Web 界面
- 资金无硬性要求，小资金可做回测 + AI 选股信号
- **缺点**：A股没有原生券商自动交易网关，自动下单需二次开发；AkShare 免费行情有延迟、Tick 数据缺失；项目偏新，社区案例少

## 四、资金门槛

### 核心结论

- **开源框架本身没有资金门槛**，几千块都可以跑回测和研究
- **资金门槛只来自券商闭源终端**（QMT/PTrade，很多券商要求 50 万资产），开源方案不需要
- "10 万最佳实践"不是硬性要求，而是**多因子分散选股策略的最小舒适资金**

### 工具门槛 vs 策略资金门槛

| 类型 | 门槛 | 说明 |
|---|---|---|
| 开源框架（vn.py等） | 无 | 本地跑回测、研究一分钱不用进股市 |
| 券商闭源终端（QMT/PTrade） | 50万资产 | 不属于开源方案，可直接排除 |
| 多因子分散选股策略 | ~10万 | 持仓10-20只股票，每只5000元，需要分散 |
| ETF轮动/单标的趋势 | 几千~几万 | 候选池小，不需要分散 |

### 不同资金体量适合的策略

| 资金量 | 适合策略 | 限制 |
|---|---|---|
| **1万~5万** | ETF轮动、单/双标的趋势、AI舆情选股（信号+人工下单） | 不能分散到十几只个股；交易成本占比高；调仓不能太频繁 |
| **10万~50万** | 多因子选股，持仓8~20只A股，中低频调仓 | 散户量化"最佳实践区间"，可充分分散 |
| **50万以上** | 多策略组合、行业中性 | 依然不适合高频（需极速柜台） |

### A股 1手 = 100股的约束

- 多因子策略目标持仓 10~20 只，每只分配 0.5 万 → 10 万
- 低于 10 万，最多买 3~5 只，风险高度集中，策略统计效果变差

## 五、ETF vs 多因子（两个维度的概念）

### 核心区别

- **ETF**：是**交易标的**（你买的东西），像股票一样买卖的指数基金
- **多因子**：是**选股/选品的决策模型**（一套挑选规则），决定买什么、什么时候买
- 类比：ETF 相当于"菜"；多因子相当于"挑选菜的一套打分标准"
- **可以用多因子模型选 ETF，也可以用多因子模型选个股**

### ETF 特点

- 一篮子打包股票，买1份=同时买一堆股票
- 个股暴雷风险被分散，波动比单只个股小
- 交易规则和股票一样：T+1，1手起，有佣金，免印花税

### 关键区分：候选池 vs 持仓量

| 概念 | 含义 | 决定了什么 |
|---|---|---|
| **候选标的池** | 每次调仓时参与因子计算、打分的全部标的 | 决定是否需要高性能批量回测引擎 |
| **目标持仓数量** | 打分后最终实际买入持有的标的数量 | 主要决定需要多少本金、分散风险 |

### 两种场景对比

| 场景 | 候选池 | 持仓 | 批量回测需求 | 资金 |
|---|---|---|---|---|
| **全A股多因子** | 4000+ 股票 | 10~20只 | ⭐⭐⭐ 需要高性能引擎 | ≥10万 |
| **ETF多因子轮动** | 10~20只 ETF | 1~3只 | ⭐ 不需要，普通框架够用 | 几千元 |

> 同样是"多因子打分+按月调仓"，候选池规模不同，对回测引擎的性能要求完全不一样。

## 六、硬件要求

### 两种场景硬件对比

| 项目 | ETF候选池（10~20只） | 全A股候选池（4000+股票） |
|---|---|---|
| CPU | 4核即可 | ≥6核，多核优先 |
| 内存 | 8GB保底，16GB推荐 | 16GB保底，32GB推荐 |
| 硬盘 | SSD可选，空间要求低 | 必须SSD，空间要求更高 |
| GPU | 不需要 | 常规多因子不需要；深度学习才需要 |
| 单次回测耗时 | 几秒~十几秒 | 几十秒~数分钟 |
| 笔记本可行性 | 普通笔记本完全可以 | 高性能笔记本可以；8G轻薄本会很卡 |
| 推荐开发环境 | 本地PC/Mac | 本地高性能PC，或低成本云服务器（4核32G） |

### 关键点

- 压力来自**候选池大小+数据量**，不是持仓多少
- 全A股回测：每次调仓日都要遍历4000多只股票做指标运算
- 8G内存跑全市场：会爆内存、频繁读写硬盘，回测从几分钟拉长到几十分钟
- 分钟线数据会进一步抬高硬件门槛（日线几十GB，分钟线上百GB）
- 云服务器替代：4核32G按量付费，跑回测时开机，平时关机

## 七、AI 舆情因子方案对比（待验证）

### 任务定义

输入新闻/财报段落 → 输出标准化分数（如 [-1,0,1]，-1利空/0中性/1利好）
属于结构化分类任务，不是深度推理，不需要超大模型。

### 方案对比

| 方案 | 优点 | 缺点 | 成本 | 适合场景 |
|---|---|---|---|---|
| **豆包 API（火山引擎）** | 中文好、接入简单、无需本地硬件 | 文本外发、按调用量付费 | 按量付费 | 快速验证、中小规模批量 |
| **Grok API** | 实时X平台信息、英文强 | 中文财报可能弱、需科学上网 | 订阅/按量 | 美股/全球市场舆情 |
| **本地开源模型（Qwen 7B/14B）** | 数据不外发、长期高频成本低、私有化 | 需GPU硬件+运维、部署复杂 | 一次性硬件投入 | 不想外发敏感文本、长期高频批量 |

### 本地开源模型推荐

- **Qwen（通义千问）7B / 14B Instruct**（首选）：中文原生最好，A股财报/公告/新闻理解强，部署成熟，输出结构化JSON稳
- **DeepSeek 7B / 14B**：金融文本表现不错，长文本（财报）解析能力强
- **Llama3 8B**：英文强，中文弱，不优先A股场景
- **不推荐 70B 级别**：显存开销巨大，单纯打分收益提升很小，性价比极低

### 本地模型 GPU 需求（INT4量化）

| 模型 | INT4显存占用 | 最低显卡 | 整机内存 |
|---|---|---|---|
| Qwen-7B | ~4-5GB | RTX3060 12GB / RTX4060Ti 16GB / Mac M Pro 16G | ≥16GB，推荐32GB |
| Qwen-14B | ~8-10GB | RTX4070Ti / RTX4080 16GB起步，推荐4090 24GB | ≥32GB |

### 关键结论

- **做打分，绝大多数场景不需要全量训练**，提示词工程 + RAG 就够用
- **优先用豆包 API 快速验证**，不要一上来就买显卡
- 本地模型适合：不想把财报/新闻文本外发、长期高频批量打分
- Grok API 调用量：ETF场景每次只请求十几条行业新闻，量小；全A股场景4000只股票财报/新闻，调用量巨大，成本高
