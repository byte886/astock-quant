## 二、竞品 A（B站）：涨停预警系统

### 2.1 核心功能

#### （1）涨停板自动扫描与打分
- 每日自动扫描全市场涨停股
- 自动打分分级：A级（最强）、B级、C级
  - 示例：某日 A级37只 / B级40只 / C级11只
- 打分维度：封单多少、封单强度、几点封板、炸过几次
- 每只股票旁边写明打分理由

#### （2）涨停类型拆分
- 换手板：示例77只
- 一字板：示例7只（基本买不进）
- T字板：示例2只

#### （3）市场情绪监控
- 15日打板情绪曲线
- 近5日均值：示例72.8只涨停，炸板率22.6%
- 当日数据与均线对比，判断情绪在回暖/降温通道
- 炸板率统计：示例25.4%

#### （4）质地体检（排雷）
- 亏损公司标记：示例88只涨停里36只是亏损公司
- ST/*ST 标记：示例13只
- 红标直接帮助排雷
- 核心逻辑：涨停不等于值得买

#### （5）解禁雷区
- 未来两周解禁自动扫描
- 示例：航天制造解禁111亿
- 提前预警"闷杀雷"

#### （6）龙虎榜资金性质
- 游资/北向资金/机构席位一眼看清
- 示例：游资8席、北向资金吸筹、机构1席
- 资金性质判断：游资主导=短线博弈，次日冲高是卖点

### 2.2 技术特点
- 一键刷新，浏览器直连交易所
- 不用装环境（Web端）
- 数据时效提示（盘前提示是昨天的数据，龙虎榜未公布说明原因）
- 代码全部免费开源

### 2.3 对我们项目的启发
- **排雷/风控层很重要**：涨停股里大量是亏损/ST股，需要自动过滤
- **情绪指标可视化**：15日情绪曲线+均线，直观判断市场温度
- **资金性质分析**：龙虎榜数据可以作为辅助因子
- **解禁预警**：事件驱动型风险因子
- **Web端免安装**：降低使用门槛

## 三、竞品 B（抖音）：DeepSeek Harness 驱动的 AI 量化系统

### 3.1 整体架构

```
DeepSeek Harness（驱动层/控制层）
    ↓ 控制
多个写死的量化引擎（Skill 流程化）
    ↓ 数据流通
120+ 因子（经过回测验证）
    ↓
动态风控层（AI设计，每日重算）
    ↓
决策层（Pick层）
    ↓
输出：选股结果 + 风险对冲规则
```

### 3.2 核心设计理念

#### （1）AI 作为驱动层，而非直接决策
- 传统量化让 AI 直接产生信号 → 幻觉问题严重
- 本系统：DeepSeek Harness 作为**驱动层**，控制多个**写死的量化引擎**
- 每个引擎有固定流程（Skill），AI 按流程调用，减少主观发挥空间
- 类比：给 AI 做了一双"好手"，而不是让 AI 凭空发挥

#### （2）主观低频量化（放弃高频）
- 高频量化是机构的游戏，需要：算力、Tick级数据、极速网速
- 散户做不了高频 → 主动放弃
- 定位：主观低频量化 + AI选股策略

#### （3）可无限进化
- 模块化设计，每个模块由 API 接口驱动
- 数据流通，每天数据变化系统跟着变
- 自然语言控制："我要升级什么、我要挖什么因子" → AI 自动加入系统
- 有 bug 直接说，让它改

### 3.3 核心功能

#### （1）120+ 因子库
- 每个因子都经过引擎回测，证明有效
- 洁面（应该是"截面"）也做了
- 因子推荐：抓到全市场机会

#### （2）动态风控层
- AI 设计的风控层
- 每天自动重算，监控因子衰减程度、排名变化
- 扫描掉有危险的股票
- 过了风控层才进入决策层

#### （3）决策层（Pick层）
- 质量因子推荐
- 回测有效、最强因子
- 识别"被错杀的股票、长期超卖"
- 回撤策略

#### （4）风险对冲规则（写死，不用动脑子）
- 回撤超20%就卖
- RE（应该是某个指标）跌破10就卖
- 止盈点都设计好
- 分长线和短线

#### （5）ETF 映射（保守选项）
- 发现问题：portfolio 回测的回撤规则，收敛到个股不一定有效
- 保守型用户可以买 ETF
- 做了 ETF 相关性映射
- ETF Pick 策略

#### （6）板块圈选
- 可以圈选板块
- 主观在前，量化在后（也可以量化在前，主观在后）

#### （7）自然语言控制一切
- 改 UI 颜色、去掉元素、加 UI
- 改系统加权程度
- 加功能、挖因子
- 报 bug 让它改

#### （8）共享数据的 AI 助手（牛仔）
- 共享量化系统所有数据
- 可以问"今天会买入什么"
- 模拟不同操作风格（不追高、不买ST、核心仓、不碰慢票等）
- 示例判断："上车寒武纪"、"宁愿买茅台"
- 跟谁的粉丝学，就跟谁的风格

### 3.4 部署要求
- **需要 API**：GPT API（实际应该是 DeepSeek API），AI驱动的核心
- **需要数据库**：系统自带一些小数据（tushare 接口），因子数据也带着
- **数据需自行购买**：tushare 接口数据不能合规二次传播，用户自己买数据后告诉系统存哪了，自动接入
- **部署方式**：准备放 GitHub；下载不下来可以发给 WorkBuddy 帮忙部署

### 3.5 对我们项目的启发

#### 架构层面
- **AI 驱动层 + 写死引擎**的架构值得借鉴：解决 AI 幻觉问题，让 AI 做流程控制而非直接决策
- **Skill 流程化**：每个量化步骤写成固定流程，AI 按流程调用
- **模块化 + API 驱动**：数据流通，可无限进化

#### 策略层面
- **主观低频定位**：散户放弃高频是务实选择
- **动态风控层**：每日重算因子衰减，这个很重要
- **因子库 + 回测验证**：120+ 因子都经过验证，不是拍脑袋
- **ETF 保守选项**：给风险厌恶用户提供退路

#### 交互层面
- **自然语言控制**：降低使用门槛，非技术用户也能用
- **AI 助手模拟风格**：共享数据，学习不同操作风格
- **Web UI 可定制**：自然语言改界面

#### 数据层面
- **数据合规问题**：tushare 数据不能二次传播，需要用户自己买
- **数据库是必须的**：因子数据、行情数据都需要存储

## 四、两个竞品对比总结

| 维度 | 竞品 A（涨停预警） | 竞品 B（AI量化系统） | 我们项目可借鉴 |
|---|---|---|---|
| **定位** | 工具型（预警+排雷） | 系统型（选股+风控+决策） | 先工具后系统，逐步扩展 |
| **AI 角色** | 未明确提 AI | 核心驱动层（Harness） | AI 做舆情因子+流程控制 |
| **策略类型** | 涨停板/打板 | 主观低频多因子 | 待确定（ETF轮动/多因子） |
| **风控** | 排雷（亏损/ST/解禁） | 动态风控层+因子衰减 | 两者结合：基础排雷+动态风控 |
| **数据来源** | 浏览器直连交易所 | tushare（需用户自购） | AkShare免费起步，后续评估付费 |
| **部署** | Web端免安装 | GitHub+需API+数据库 | 先本地，后续评估Web化 |
| **开源** | 免费开源（私信获取） | 准备开源（GitHub） | 纯开源路线 |
| **目标用户** | 打板散户 | 所有散户 | 自己（先自用） |

## 五、对我们项目的需求输入（待讨论确认）

基于两个竞品的调研，以下是可能纳入我们项目的需求点，**需要对比讨论后确定优先级**：

### 5.1 高优先级（核心能力）
- [ ] **数据获取层**：A股行情数据（AkShare起步），支持日线/分钟线
- [ ] **因子计算引擎**：技术因子+基本面因子，可扩展
- [ ] **回测引擎**：支持策略回测，输出绩效指标（年化/回撤/夏普/胜率）
- [ ] **风控/排雷层**：ST/*ST、亏损、解禁、退市风险等基础排雷
- [ ] **信号输出**：盘后选股信号，人工下单（起步阶段）

### 5.2 中优先级（增强能力）
- [ ] **AI 舆情因子**：大模型对新闻/财报做情绪打分，作为辅助因子
- [ ] **动态因子监控**：因子衰减程度、有效性排名
- [ ] **市场情绪指标**：涨停数/炸板率/情绪曲线
- [ ] **ETF 轮动策略**：保守型策略选项
- [ ] **板块/行业分析**：板块圈选、行业轮动

### 5.3 低优先级（远期扩展）
- [ ] **自然语言交互**：自然语言控制策略/改参数
- [ ] **Web UI**：可视化界面，免安装
- [ ] **自动下单**：对接券商 API（需评估合规和门槛）
- [ ] **AI 助手模拟风格**：共享数据的对话式助手
- [ ] **龙虎榜资金分析**：游资/机构/北向资金因子

### 5.4 需要用户决策的问题
1. **策略方向**：先做 ETF 轮动（简单、小资金友好）还是直接做多因子选股（需要10万+资金）？
2. **AI 因子方案**：豆包 API / Grok / 本地开源模型，选哪个？
3. **框架选型**：vn.py / QuantDinger / qlib / Hikyuu，主框架选哪个？
4. **数据方案**：AkShare 免费起步，还是直接上 Tushare 付费？
5. **执行方式**：盘后信号+人工下单，还是要自动下单？
