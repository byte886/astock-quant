# ADR-006 · 统一每日增量更新机制 + 增量直写 Parquet（T35）

- 日期：2026-09-26
- 项目：astock-quant
- 状态：Accepted
- 关联：ADR-004（CSV/Parquet 双轨）、ADR-005（计算引擎分工）

## 背景 / 面对什么问题

1. 全量历史已下完并逐只核对：个股 **4602**（剔除科创板688/北交所）、ETF **1588**，日线与 5 分钟线 0 缺失。但行情每个交易日仍在新增，数据必须「每天保鲜」，否则回测/扫描/模拟盘很快用过时数据。
2. ADR-004 的双轨里，Parquet 原本由 `csv_to_parquet.py` **事后批量转换**。增量若只更新 CSV，就会出现「CSV 已到今天、Parquet 还停在昨天」的不一致窗口（T35 要消除它）。
3. 物理约束：baostock 逐只串行、按 IP 限流，且**同一账号多进程/多连接并发登录会挂起**（W3）。6190 只标的的 5 分钟线「每天盘后全轮一遍」在盘后窗口内做不到（实测一次只拉 3 天日线的查询都可能挂起数分钟）。

## 决策

落地一个**统一增量 worker**（`scripts/incremental_update.py`）：

1. **单进程常驻 + 单例**：`fcntl.flock` 保证只跑一个；launchd `RunAtLoad + KeepAlive` 崩溃自愈，豆包关了、重启后都继续。baostock 全程只 login 一次、所有查询串行。
2. **盘后优先级队列**（交易日 15:05 数据齐后）：
   - ① 核心池四类先更新：个股=中证800（约706）、ETF=`config/core_etfs.csv`（30只，已剔除科创50ETF）；
   - ② 全市场**日线**（个股4602 + ETF1588）分批、游标、断点续传，补到当天；
   - ③ 全市场 **5 分钟线滚动追赶**：核心已在①每天更新，其余按游标循环轮转、逐步逼近最新。
3. **增量直写双轨（T35）**：每只合并去重后，同一次运行里写 CSV 底稿并直接生成 Parquet（复用 `csv_to_parquet.typeify`，原子落地），消除双轨时间差。读取层仍「Parquet 优先、CSV 回退」。
4. **避让**：交易时段 9:25–15:05 不跑 baostock；非交易日（周末/节假日）不跑分钟滚动（历史已齐、无新数据，且 baostock 周末常挂起）。
5. **职责收拢**：`daily_after_close.sh` 精简为只推进模拟盘（18:30 时 worker 已把数据备好），避免两个进程并发 baostock；全量使命完成后 bootout `download-data`、`fundamentals` 的 launchd（plist 保留可恢复）。

## 备选方案（放弃的）

- **A. 多个 launchd 分别跑日线 / 分钟滚动**：天然并发，触发 baostock 同账号登录挂起（W3），放弃。
- **B. 5 分钟线全市场每天全轮**：盘后窗口物理上跑不完，放弃，改为核心每日 + 全市场滚动。
- **C. 只写 CSV、事后再批量转 Parquet**：保留双轨不一致窗口，放弃，改为增量当次直写。

## 后果 / 何时重新评估

- 全市场非核心标的的 5 分钟线会**滞后若干天**（取决于滚动一圈耗时）；核心池每日新鲜，策略实际只用核心池，不影响。
- 单只增量需重写整文件（分钟 CSV 较大），有 IO 开销，靠夜间窗口消化。
- 首次真实运行在 **2026-09-28（周一）盘后**，需验证：核心四类真更新、全市场日线游标推进、CSV 与 Parquet 同日一致、滚动游标落盘。
- 若将来接入付费实时源或更快数据通道，可重估「全市场分钟每日更新」的可行性。
