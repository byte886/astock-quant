# ADR-007 · 盘中监控巨石单文件模块化重构 + 引入确定性质量门（clean-code-gauntlet）

- 日期：2026-10-12
- 项目：astock-quant
- 状态：Accepted
- 关联：`docs/REQUIREMENTS.md` §5.8、`docs/板块异动监测_上线说明.md`（v2）、`docs/盘中监控重构报告_gauntlet质量改造_2026-10-12.md`、`EQUIVALENT-MUTANTS.md`

## 背景 / 面对什么问题

1. 盘中板块异动监测器 2026-09-24 上线后高频迭代，逻辑全部堆在单文件 `scripts/intraday_sector_monitor.py`（约 1264 行），核心判定函数 `_eval_board` **圈复杂度高达 86**；判定与网络/读写文件/发消息等副作用缠绕，时间直接取 `datetime.now()`，**无法做离线、确定性的回归测试**。
2. 这套系统替操盘手盯盘、输出直接影响盘中决策，却接连出现只能靠人盯日志才发现的问题：I13（异常静默，上午 30 个 `NameError` Traceback、监控空转）、I15（重启后把一直达标的板块当新启动、重复推送）、I16（腾讯兜底代码带 `sh/sz/bj` 前缀导致 20cm 涨停按 10cm 误判、920 北交号段被误归上海，板块涨停数虚高）。"AI 写的代码能不能信"缺少客观证据。
3. 跨任务窗口交接时，质量靠文字承诺、不可复现；需要一套**机器可判定**的放行标准，而不是"跑过几次没报错"。

## 决策

1. **判定纯函数化 + 副作用集中**：板块分级、消退宽限、波次、文案改为无 IO 纯函数（时间/随机/网络全部作参数注入，同样输入必得同样输出）；网络采集、读写文件、推送分别收拢到 `datasources / persistence / notifier`。
2. **拆分层包 + 薄入口**：业务逻辑迁入 `src/monitor/`（`config→codes→datasources→aggregator→statemachine→persistence→notifier→reconcile→monitor→cli` 单向依赖），用 import-linter 契约强制（写在 `pyproject.toml`），违规/循环依赖必须为 0；`scripts/intraday_sector_monitor.py` 退为约 20 行薄入口；原单文件备份留存 `data/_workspace/`（gitignore）。
3. **引入 clean-code-gauntlet 六道门作为合并/发布的机器强制关卡**：最大圈复杂度 ≤8、CRAP <30、核心覆盖率 ≥80%、存活变异 =0（人工核验为等价体的登记 `EQUIVALENT-MUTANTS.md` 后用 `--equiv-ok` 豁免）、架构违规/循环依赖 =0、DRY 重复候选 =0；关卡映射写 `quality-gates/tools/python.yaml`，工具 vendor 置于项目外。日常提交跑轻量 commit 门（复杂度+覆盖率），合并/发布跑全量 merge 门。
4. **行为守恒式重构**：切换前用固定时钟、固定随机种子，对包版与原单文件版做 4 板块 × 80 轮状态机全流程 + 纯函数差分，**完全等价才上线**，不借重构之名改行为。
5. **同期补齐可靠性与口径**：状态机增强（状态持久化、10 分钟消退宽限、波次计数、固定原因标签，治 I15）；防静默三道（每轮全板块快照、交易时段首轮全源失败自检、30 分钟无成功扫描看门狗 + 恢复通知）；推送读企微 errcode 回执；东财/腾讯双源同时点对账（I14，纯观测不改触发）；I16 涨停口径修复。
6. **部署门禁与红线**：上线脚本先备份→替换→字节比对→编译→跑 19 个离线状态机场景，任一失败自动 `git checkout` 回滚；交易时段禁止改代码/重启，重启只在午休或收盘后。
7. **过程产物治理**：`.metrics/`、`.coverage`、`target/`（含 merge 门日志与阶段签收单）gitignore、本地留存供阶段审查；放行依据（`EQUIVALENT-MUTANTS.md`、gates 配置、契约）入库随代码走。

## 备选方案（放弃的）

- **A. 继续在单文件上打补丁**：CC=86 的函数无法被有效、确定性地测试，I13/I16 类问题必然复发，放弃。
- **B. 推倒重写、不保留原行为**：监控正在盘中服役，重写极易产生行为漂移、漏信号，放弃；改为行为守恒式重构，用固定种子差分守门。
- **C. 只补单元测试、不拆结构**：巨石函数分支不可达、CRAP 极高，覆盖率会虚高、测不到关键路径，放弃。
- **D. 用文字 checklist 代替质量门**：靠人自觉、跨窗口不可复现，放弃；改为 `gates.yaml` + 工具的机器强制（规则代替文字）。

## 后果 / 何时重新评估

- 合并成本上升：全量 merge 门含变异测试，单次数分钟；日常用秒级 commit 门自检，仅合并/发布跑全量。
- 架构契约当前只覆盖 `src/monitor`；量子系统 `src/quant` 不在范围（另有约 3 处 DRY 已记录），后续改造量子系统时再扩展契约。
- 等价变异体豁免依赖人工核验，今后新增豁免**必须**在 `EQUIVALENT-MUTANTS.md` 留证据（含手动改坏源码的反证），不得直接 `--equiv-ok` 放行。
- 包版 + 薄入口的**首次盘中实战为 2026-10-13**，需核验首轮扫描、企微推送与双源对账（跟踪任务 #10/#12）。
- 若 gauntlet 上游工具大版本变更、或项目引入新语言栈，重评本工具链与阈值。
