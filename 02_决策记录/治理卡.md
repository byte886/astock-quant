# 治理卡 · 项目决策权限与边界

> 最后更新：2026-09-16
> 明确：什么事自己能定、什么情况必须停下重评。

## 1. 可独立决定（无需确认）

- 调研方法、资料收集渠道、文档整理方式
- 项目目录结构、文件命名、代码框架搭建
- 开源工具的安装、配置、测试
- 回测实验的参数调整（不涉及真金白银）
- 研究笔记、对比文档的撰写

## 2. 必须暂停重评（需要用户确认）

- **框架选型**：最终选定哪个量化框架作为主框架
- **AI 方案选型**：最终用豆包 API / Grok / 本地模型哪个
- **策略方向**：全 A 股多因子 vs ETF 轮动，候选池规模
- **资金投入**：任何涉及真金白银的决策
- **实盘操作**：从回测到实盘的切换、自动下单的启用
- **付费服务**：任何需要花钱的工具/数据/API 订阅
- **项目重大变更**：目标、成功标准、期限的调整

## 3. 暂停触发条件（出现以下情况立即停下）

- 进度偏离计划超过 2 周
- 预算/工具费用超预期 20%
- 新风险使核心假设失效（如 AI 因子回测完全无效）
- 用户提出新的方向或约束

## 4. 碰节奏

- 每完成一个调研节点（视频提取、框架对比等），更新一次 TASK_STATUS
- 每次产生关键决策，写入 `02_决策记录/`
- 项目总纲在阶段切换时更新

## 5. 决策记录规范

每个关键决策写一条 ADR（Architecture Decision Record），格式：

```markdown
# ADR-XXX：<决策标题>

- 日期：YYYY-MM-DD
- 状态：已决定 / 待确认 / 已废弃

## 背景
<为什么要做这个决策>

## 选项
- 选项 A：<优缺点>
- 选项 B：<优缺点>

## 决定
<选了什么，为什么>

## 后果
<这个决策带来的影响和约束>
```
