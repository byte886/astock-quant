# 新窗口怎么接手这个项目（开新任务窗口 · 固定 SOP）

> 目标：**只要知道仓库位置，新窗口就能接手**，不需要你复述背景。
> 权威恢复顺序以根 `AGENTS.md` §5 为准；本文件只规定"开新窗口"这句话触发的固定动作：**老窗口收口 → 你两步开窗 → 新窗口六问验收**。
> 2026-09-21 实测订正：选项目文件夹**不保证**项目 `AGENTS.md` 被自动注入（当天新窗口开场只带了全局规则和项目目录，项目规则并未出现）。真正强制冷启动的是第 2 步那句标准句——**两步都要做，标准句是兜底**。

---

## 0. 触发词（听到就走本 SOP，不自创交接长文）

用户说以下任一句，当前窗口（=**老窗口**）立即按 §1 做：

- "上下文有点大了，开个新任务窗口" / "换新窗口" / "新窗口接手" / "再开个窗口接着干"

## 1. 老窗口收口（开窗之前，AI 做，四步）

1. **状态落盘**：本轮重要讨论/决策已往 `docs/HANDOFF.md` §1 倒序追加一条；`TASK_STATUS.md`、`ISSUES.md` 更新到最新（易变进度只留在台账）。
2. **体检**：仓库根跑 `.venv/bin/python scripts/doc_health_check.py`，必须 **0 ERROR**。
3. **提交**：`git commit`；跨机（如操盘手那台 Windows 机 clone）或他人接手还要 `git push`（本机新窗口直接读本地文件，push 按惯例照做不断）。
4. **发操作指引**：把下面 §2 的两步和标准句**原样**发给用户，不要再写长篇交接段落（仓库自描述，结论都在仓里）。

## 2. 用户开窗两步（本机，推荐，最简）

1. 新建任务窗口时，**项目文件夹选成 `~/Desktop/astock-quant`**
   （不要用系统默认的 `~/Doubao/chats/...` 聊天临时目录——那里的 AGENTS.md 是旧的，会误导新窗口）。
   作用：定位仓库、工作目录落在项目里；**但不保证规则自动注入**，所以第 2 步不能省。
2. **只发这一句（标准句，原文照发）**：

   ```
   接手这个项目，按 AGENTS.md §5 冷启动，先把冷启动六问答给我听，再等我派活。
   ```

   短句"按 AGENTS §5 冷启动答六问"语义等价、同样有效。读什么、什么顺序、红线、六问，全由仓库里的 `AGENTS.md` §5 接管。

## 3. 新窗口验收（怎么算接手成功）

- 新窗口应当**不翻旧聊天**就答出冷启动六问（①项目是什么/两主线；②在哪个门、最近完成什么；③下一步与待拍板项+推荐；④开放问题/坑/数据缺口；⑤红线；⑥关键命令），清单原文见 `AGENTS.md` §5 与 `docs/项目维护SOP.md` §6。
- 老窗口可让新窗口把六问答出来，抽查 1~2 条与 `TASK_STATUS.md` 对得上。
- 答不上、或文档之间自相矛盾 → **不开工**，先按 `docs/项目维护SOP.md` §5 修文档（这说明仓库自描述有缺口）。

## 4. 兜底（他人接手 / 网页版 / 无法选项目文件夹 / 换了新 Mac）

- **新 Mac 先 clone**：`git clone git@github.com:byte886/astock-quant.git`，再把文件夹选成克隆目录，其余同 §2。
- 没法让系统读到项目 `AGENTS.md` 时，复制下面整段发给新窗口（已带仓库路径，阅读顺序与 `AGENTS.md` §5 一致）：

```
接手一个进行中的项目，仓库在 ~/Desktop/astock-quant（GitHub: github.com/byte886/astock-quant，public，main）。
这是 A 股量化「量子系统」+ 为职业操盘手做「交易外脑」的双主线项目，当前在 G2 验证门已过、准备 G3 模拟盘阶段。

请严格按仓库根 AGENTS.md §5「新会话恢复顺序」冷启动，不要凭文件名猜测、不要直接写代码，按顺序读：
1. AGENTS.md → 2. README.md → 3. 00_项目总纲.md → 4. docs/DOCUMENTATION_MAP.md
→ 5. docs/HANDOFF.md（§1 倒序日志 + §3 当前纠结）→ 6. docs/WORKFLOW.md §0 判阶段
→ 7. 03_进行中的任务/TASK_STATUS.md → 8. 03_进行中的任务/ISSUES.md。
读完用 docs/项目维护SOP.md §6「冷启动验收」自测，并把六个答案讲给我听：
项目是什么/两条主线、现在在哪个门最近完成了什么、下一步与待我拍板项及你的推荐、
开放问题与已知坑、红线、关键命令。六问答不上来先修文档再动手。

红线：不自动下单、不替操盘手定交易参数、不承诺收益、不给具体买卖建议；
data/ 与 results/ 不入库、凭证只走环境变量；09_调研底稿与素材/ 原始素材只读。
改文档/脚本后跑 .venv/bin/python scripts/doc_health_check.py，提交前必须 0 ERROR。
现在请先完成冷启动并汇报六问，再等我布置具体任务。
```

## 为什么至少还要"选文件夹 / 给路径"这一步

新对话默认不知道你要它接手**哪个**项目（你电脑上不止一个项目），所以"告诉它仓库在哪"省不掉——这本身就是"只需知道仓库位置"。
位置一旦给了（选文件夹 = 给位置），**读什么、什么顺序、答哪六问、红线是什么，全部由仓库里的 `AGENTS.md` 和 `docs/项目维护SOP.md` 接管**；标准句再强制一次冷启动，不依赖自动注入是否生效，不需要你解释任何来龙去脉。
