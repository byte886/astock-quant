# 新窗口怎么接手这个项目

> 目标：**只要知道仓库位置，新窗口就能接手**，不需要你复述背景。
> 权威恢复顺序以根 `AGENTS.md` §5 为准；本文件只讲"怎么开口"。

---

## 方式一 · 本机新建任务（推荐，最简，两步）

1. 新建任务窗口时，**项目文件夹选成 `~/Desktop/astock-quant`**
   （不要用系统默认的 `~/Doubao/chats/...` 聊天临时目录——那里的 AGENTS.md 是旧的，会误导新窗口）。
   选定后，豆包会**自动把本目录的 `AGENTS.md` 作为项目规则注入**，新窗口一开场就自带恢复顺序、红线和六问，不用你贴任何背景。

2. 只发这一句：

   ```
   接手这个项目，按 AGENTS.md §5 冷启动，先把冷启动六问答给我听，再等我派活。
   ```

就这一句。读 README、项目总纲、文档地图、WORKFLOW、TASK_STATUS、ISSUES、HANDOFF 的顺序和红线，它会自己按 AGENTS.md 走。

> 换台 Mac：先 `git clone github.com/byte886/astock-quant`，再把文件夹选成克隆出来的目录，同上。

## 方式二 · 兜底（他人接手 / 网页版 / 无法选择项目文件夹时）

没法让系统自动注入 AGENTS.md 时，再复制下面整段（里面已带仓库路径）：

```
接手一个进行中的项目，仓库在 ~/Desktop/astock-quant（GitHub: github.com/byte886/astock-quant，public，main）。
这是 A 股量化「量子系统」+ 为职业操盘手做「交易外脑」的双主线项目，当前在 G2 验证门已过、准备 G3 模拟盘阶段。

请严格按仓库根 AGENTS.md §5「新会话恢复顺序」冷启动，不要凭文件名猜测、不要直接写代码：
1. README.md → 2. 00_项目总纲.md → 3. docs/DOCUMENTATION_MAP.md → 4. docs/WORKFLOW.md §0 判阶段
   → 5. 03_进行中的任务/TASK_STATUS.md + ISSUES.md → 6. 第三方/外脑先读 docs/HANDOFF.md。
读完用 docs/项目维护SOP.md §6「冷启动六问」自测并把六个答案讲给我听：
项目是什么/两条主线、现在在哪个门最近完成了什么、下一步与待我拍板项及你的推荐、
开放问题与已知坑、红线、关键命令。六问答不上来先修文档再动手。

红线：不自动下单、不替操盘手定交易参数、不承诺收益；data/ 与 results/ 不入库、凭证只走环境变量；
改文档/脚本前后跑 .venv/bin/python scripts/doc_health_check.py，提交前必须 0 ERROR。
现在请先完成冷启动并汇报六问，再等我布置具体任务。
```

## 为什么至少还要"选文件夹 / 给路径"这一步

新对话默认不知道你要它接手**哪个**项目（你电脑上不止一个项目），所以"告诉它仓库在哪"这一步省不掉——这本身就是"只需知道仓库位置"。
位置一旦给了（选文件夹 = 给位置），**读什么、什么顺序、答哪六问、红线是什么，全部由仓库里的 `AGENTS.md` 和 `docs/项目维护SOP.md` 接管**，不需要你再解释任何来龙去脉。

## 怎么算接手成功

新窗口应当**不翻旧聊天**就答出冷启动六问：①项目是什么/两主线；②在哪个门、最近完成什么；③下一步与待拍板项+推荐；④开放问题/坑/数据缺口；⑤红线；⑥关键命令。
答不出、或文档之间自相矛盾，说明仓库自描述有缺口——让它先按 `docs/项目维护SOP.md` §5 补文档，而不是带着错误认知开工。
