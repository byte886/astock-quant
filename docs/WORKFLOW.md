## 整体流水线

```
阶段① 数据采集与管理 → 阶段② 框架选型与环境搭建 → 阶段③ 策略研发与因子工程 → 阶段④ 信号产出与验证
   (数据)                (选型)                      (研发)                      (验证)
```

| 阶段 | 目标 | 核心产出 | 校验门 |
|------|------|---------|--------|
| ① 数据采集与管理 | 建立稳定的A股历史数据源，覆盖尽量完整的历史 | Baostock 全量日线/财务数据、股票列表、数据质量报告 | 数据覆盖率、完整性、可复现下载 |
| ② 框架选型与环境搭建 | 对比选定量化框架和AI因子方案，搭建开发环境 | 框架选型报告、AI因子方案报告、可运行的开发环境 | 选型有依据、环境可复现、最小demo跑通 |
| ③ 策略研发与因子工程 | 实现最小可用策略，完成因子计算和回测 | 策略代码、因子库、回测结果、绩效报告 | 回测覆盖≥3年、绩效指标完整、策略可复现 |
| ④ 信号产出与验证 | 产出盘后交易信号，验证策略有效性 | 每日信号报告、实盘/模拟验证记录、迭代优化记录 | 信号可追溯、验证有记录、策略持续迭代 |

## 阶段①：数据采集与管理

### 1.1 子环节
1. **股票列表获取**：从 Baostock 获取全部A股股票列表（含上市/退市状态）
2. **日线数据下载**：按股票逐只下载日线数据（1990年至今），间隔2-3秒防限流
3. **财务数据下载**：下载主要财务指标（资产负债表、利润表、现金流量表）
4. **复权因子下载**：下载前复权/后复权因子
5. **数据质量检查**：覆盖率统计、缺失值检查、异常值检测
6. **增量更新机制**：每日收盘后只下载新增数据

### 1.2 校验门（阶段完成标准）
- [ ] 股票列表覆盖全部A股（含已退市，去重后数量合理）
- [ ] 日线数据覆盖率 ≥ 95%（每只股票有数据的交易日占上市以来总交易日的比例）
- [ ] 数据可复现下载（脚本可重新运行，断点续传）
- [ ] 数据质量报告已生成（覆盖率、缺失、异常）
- [ ] 增量更新机制可用（每日只下载新数据）

### 1.3 参考文档
- 数据下载脚本：`scripts/download_data.py`（待创建）
- 数据来源与凭证：[AGENTS.md](../AGENTS.md) 第3节（工具用法与坑）

## 阶段②：框架选型与环境搭建

### 2.1 子环节
1. **开源量化框架横向对比**：vn.py / QuantDinger / qlib / Hikyuu / Backtrader，从功能、社区、文档、学习曲线、A股适配度等维度对比
2. **AI 舆情因子方案对比**：豆包 API / Grok / 本地开源模型，从成本、准确率、部署难度、调用限制等维度对比
3. **候选池规模确定**：全 A 股 vs ETF 小池，决定硬件要求和回测引擎
4. **开发环境搭建**：Python 环境、依赖安装、目录结构确认
5. **最小 demo 跑通**：用选定框架跑一个最简单的回测（如买入持有策略）

### 2.2 校验门（阶段完成标准）
- [ ] 量化框架选型报告已完成（有对比表、有推荐、有理由）
- [ ] AI 因子方案选型报告已完成（有对比、有推荐、有理由）
- [ ] 候选池规模已确定
- [ ] 开发环境可复现（requirements.txt 或等价物）
- [ ] 最小 demo 跑通（选定框架可正常回测）

## 阶段③：策略研发与因子工程

### 3.1 子环节
1. **最小可用策略设计**：数据获取 → 因子计算 → 回测 → 信号输出
2. **因子库建设**：基础因子（动量、价值、质量、波动率等）+ AI 舆情因子
3. **回测执行**：覆盖至少3年A股历史数据，完整绩效指标
4. **参数敏感性分析**：关键参数对绩效的影响
5. **过拟合检测**：样本内/样本外对比

### 3.2 校验门（阶段完成标准）
- [ ] 最小可用策略跑通（完整链路：数据→因子→回测→信号）
- [ ] 回测覆盖至少3年A股历史数据
- [ ] 绩效指标完整（年化、最大回撤、夏普、胜率、盈亏比）
- [ ] 策略代码可复现（参数固定、数据固定、结果可重跑）
- [ ] 因子文档齐全（每个因子有定义、计算方法、预期方向）

## 阶段④：信号产出与验证

### 4.1 子环节
1. **盘后信号生成**：每日收盘后运行策略，产出交易信号
2. **信号报告**：每日信号清单（买入/卖出/持有）、理由、仓位建议
3. **模拟盘验证**：用模拟盘跟踪信号表现
4. **实盘小资金验证**：人工下单，小资金试跑
5. **策略迭代优化**：根据验证结果持续优化

### 4.2 校验门（阶段完成标准）
- [ ] 每日信号可自动生成（脚本可定时运行）
- [ ] 信号报告清晰（标的、方向、理由、仓位）
- [ ] 模拟盘验证有记录（至少1个月）
- [ ] 实盘验证有记录（如进入实盘阶段）
- [ ] 策略迭代有文档（每次修改的原因和效果）

## 阶段间依赖与并行
- 阶段①（数据采集）可与阶段②（框架选型）并行——数据下载不依赖框架选型
- 阶段③（策略研发）依赖阶段①完成（有数据）和阶段②完成（有框架）
- 阶段④（信号产出）依赖阶段③完成（有策略）
- 中途补齐：先对照四阶段校验门，确认缺在哪一阶段，只补该阶段缺口，补完重过该门

## 全局规则（所有阶段必须遵守）

### 核心原则
1. **数据先行**：任何策略研发前必须有稳定、可复现的数据来源
2. **选型有依据**：框架和方案选型必须有对比报告，不凭感觉选
3. **回测可复现**：所有回测必须参数固定、数据固定、结果可重跑
4. **先模拟后实盘**：任何策略必须先模拟盘验证，再考虑实盘
5. **不做投资建议**：本项目仅用于个人学习研究，不构成任何投资建议

### 大任务检查与报告约定
- **子任务主动上报**：每个子任务完成后报告进度（已完成/失败/跳过）
- **定期检查防异常**：长任务（如全量数据下载）每30分钟检查一次状态
- **以脚本/接口可复算结果为准**，不凭印象判完成（如数据覆盖率、回测绩效）

### 批量任务规则
- 数据下载可按股票批量并行（并发度 ≤ 3，防限流）；阶段间必须前一阶段过门后再整体推进
- 全部完成后做一次总校验：各阶段校验门逐列复核，输出整体结果
- 断点续传：状态文件放 `data/_workspace/<任务>_status.json`，中断后从断点继续
