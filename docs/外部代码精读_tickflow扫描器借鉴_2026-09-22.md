## 0. 一句话结论

它对我们最有价值的**不是产品/面板，而是一套"指标与信号分离、每策略一个声明式文件、全程向量化"的扫描器骨架**，且技术栈与我们 ADR-004 同代。可借物分三档：

1. **架构契约（最该借）**：策略 = 一个纯函数文件，声明参数/依赖字段/预热棒数/进场/出场/止损/最长持有；指标预计算成列、策略只引用列名。正好命中我们非功能需求"新增策略只加一个文件、新增因子只加一个函数"，也直接补 I12（v1 只会当天亮灯计数、缺时序与出场）。
2. **Polars 指标写法**：`pl.scan_parquet(glob)` 懒加载 + `.over("symbol")` 分组滚动，一条表达式算完全市场；量比有明确的"标准分母"口径，可回应 I7。
3. **一批默认阈值（仅作 T30 校准候选，绝不直接采用）**：它偏短线（横盘 10 日、持有 10–20 日），操盘手是中低频/月度、横盘 3–6 个月，周期不一致。

> **修正一个认知**：上一轮我们以为它的形态信号用 Polars 计算；读代码确认是 **Polars 算指标 → 组装成 numpy 宽矩阵 → 形态/信号在 numpy 矩阵上向量化**。Polars 不负责最终的形态状态判断。

## 1. 它的真实三层架构（读代码确认）

```
Parquet（按日期 hive 分区，全市场长表）
   kline_daily_enriched/date=YYYY-MM-DD/*.parquet   列: symbol,date,OHLCV,amount,turnover_rate...
        │  pl.scan_parquet(glob)  懒加载、谓词/投影下推
        ▼
指标层  indicators/pipeline.py :: compute_indicators
   Polars .with_columns( 指标表达式.over("symbol") )  一次性算 68 列（MA/EMA/MACD/KDJ/BOLL/量比/60日高低…）
        │  组装为宽矩阵
        ▼
矩阵层  backtest/matrix.py :: MarketDataMatrix
   每个字段一个 [n_symbol × n_date] float32 二维数组；ValidBarIndex 沿"有效K线"平移（跳过停牌/NaN）；
   matrix_feature(market,"ma20"/"vol_ratio_5d") 取预计算特征（带缓存）；重型 memmap 磁盘缓存是为 Web 实时
        │
        ▼
信号层  strategy/builtin/<策略>.py :: compute_signals(matrix, params) -> SignalMatrix
   numpy 布尔矩阵向量化：entry / exit / 止损 / 最长持有；每策略一个文件，matrix_native 后端
```

### 与我们现状的布局差异（决定基准怎么设计）

| 维度 | tickflow | 我们现状 | 对选型的含义 |
|---|---|---|---|
| Parquet 分区 | **按日期**分区，全市场长表 | **一只一文件**（`data/raw/daily/<code>.parquet`） | 它做"某天全市场横截面"只读当天分区；我们需 glob 全部文件。**基准必须在我们自己的布局上实测，不能外推它的性能**；是否派生"全市场长表/按年分区"扫描专用数据集，由基准结果决定（原始一只一文件保留作底稿） |
| 指标计算 | Polars `.over("symbol")` 全市场向量化 | pandas 逐只 / `src/quant/factors.py` | 基准对比项之一 |
| 形态/信号 | numpy 宽矩阵 + shift 累积 | `pool3_scan.py` v1 逐日"要件亮灯计数"（I12） | 借其"时序窗口 + 进出场对称"思路；是否上 numpy 宽矩阵看基准与复杂度 |
| 停牌处理 | `ValidBarIndex` + `valid_shift` 沿有效 K 线平移 | 需自查现有 shift 是否把停牌 NaN 当一根 K 线 | A 类结构逻辑里要补，避免停牌制造假信号 |
| 服务形态 | FastAPI + React + Docker 常驻 | launchd + 脚本 + 静态图表（Q6 已定） | **不借** |

## 2. 最该借：策略文件的工程契约

以 `platform_consolidation_breakout.py` / `ma_convergence_breakout.py` / `pullback_to_support.py` 为例，每个策略文件固定由以下部分组成：

| 组成 | 作用 | 对我们的价值 |
|---|---|---|
| `META.id/name/description/tags/timeframes` | 策略身份与适用周期 | 001/002/003 各一文件，自描述 |
| `META.params[]`：每个参数 `id/label/type/default/min/max/step` | 参数集中声明、带取值范围 | **天然支持 T30 操盘手校准和 B6 参数敏感性分析**；阈值不再散落代码 |
| `META.scoring`：加权打分（如量比 0.4 + 动量 0.3 + 涨幅 0.3），`order_by/limit` | 多要件命中后排序出股 | 扫描器从"亮灯计数"升级为"可解释加权评分" |
| `required_fields()` | 声明依赖哪些原始字段（frozenset） | 数据依赖显式化、缺数据可提前拦截 |
| `required_warmup_bars()` | 预热棒数 | **指标未成熟不出信号，防未来函数/预热不足**（对应我们 B4） |
| `compute_signals(matrix, params) -> SignalMatrix` | **纯函数**：矩阵进、entry/exit 信号矩阵出 | 可单测、可回测、可盘后扫描共用同一份逻辑 |
| `ENTRY_SIGNALS / EXIT_SIGNALS` | 进场与出场信号对称声明 | 操盘手母版**出场规则偏弱**，这里给了完整范式（但出场阈值须操盘手确认，不替他定） |
| `STOP_LOSS / MAX_HOLD_DAYS` | 止损（-5%~-7%）、最长持有（10~20 日） | 风控 R5/R6 的落点；数值同样待校准 |

> 映射建议（待 D-17 拍板）：把 001/002/003 各做成一个"声明式规格 + 纯函数信号"的文件，参数集中在文件头；扫描器和回测器都调用同一个 `compute_signals`，避免"盘后扫描一套逻辑、历史回测另一套"（这是 I12 形似神不似的根因之一）。

### 时序条件的向量化表达（解决 I12 的关键手法）

- "**前 N 日平台（不含今日）**"：把最高价用 `shift(1)…shift(N)` 取逐日上界做 `fmax`，得到不含今日的前 N 日最高/最低，再算振幅与突破。
- "**近 N 日持续满足**"（如均线粘合 squeeze）：先算当日布尔 `tight`，再 `shift(tight,1) & … & shift(tight,N)` 累积逻辑与。
- 等价的 Polars 写法是 `布尔列.rolling_sum(N).over("symbol") == N`；基准阶段对比两种写法的可读性与速度。

## 3. 内置策略 ↔ 操盘手 001/002/003 对照

> 阈值全部是 tickflow `default`，**仅作 T30 校准的初始对照候选，未经我们数据回测、未经操盘手确认**。

| tickflow 策略（默认参数） | 对应操盘手规则 | 对应关系 / 差异 |
|---|---|---|
| **平台整理突破** `platform_consolidation_breakout`：前 10 日（不含今日）振幅 ≤8% + 收盘破前高 + 量比5d≥1.5；止损 -6%/持 15 日 | **002 右侧**：长期横盘后放量突破平台上沿 | 高度对应；但它横盘默认 **10 日**，操盘手要 **3–6 个月**，周期短很多；振幅 8%、量比 1.5 可作候选 |
| **均线粘合突破** `ma_convergence_breakout`：MA5/10/20 带宽(极差/MA20) ≤2.5% 持续 ≥5 日 + 涨幅 ≥2% + 量比≥1.2 + 收上三线；-6%/15 日 | **002**：均线粘合后向上发散 | 对应；它只到 MA20，操盘手含 MA60；粘合带宽 2.5%、持续 5 日为候选 |
| **缩量回踩** `pullback_to_support`：回踩 MA20±2% + 量比 <0.8 + 收盘在 MA60 上 + 20 日动量>0；收盘破 MA20 出场；-5%/20 日 | **001 第二阶段**：缩量回调不破前低；**002** 回踩 | 它用"MA20 附近"，操盘手用"前低/支撑"，参照系不同；**量比 <0.8 缩量**阈值可直接拿去对照 |
| **均线回踩反弹** `pullback_ma20_bounce`：MA20±2% + MA5>MA20>MA60 多头 + 当日上涨；-5%/15 日 | 001/002：站上 20 日线后的回踩确认 | 对应"20 日线由走平转上翘、股价站上后回踩不破" |
| **新低反转** `n_day_low_reversal`：触 60 日新低当日收阳 + 量比≥1.5；-6%/15 日 | **001 左侧**：长期下跌后首次放量阳线（资金试盘） | 部分对应；它是"新低当日"偏右，操盘手要"长期下跌后**间歇性**放量"，需加位置与间歇逻辑 |
| **长下影反击** `long_lower_shadow_reversal`：近 5 日跌 ≤-5% + 下影线 ≥3% + 收盘收复上半区；-5%/10 日 | **001**：底部 K 线语言/下影承接 | 对应操盘手截图里的下影线试盘语言 |
| **超跌反转** `oversold_reversal`：RSI14<30 + 涨>1% + 站上 MA5；-5%/15 日 | 001 超卖辅助 | 操盘手母版未明确用 RSI，仅作可选辅助指标 |
| **量价齐升** `volume_price_surge`：破 MA20 + 量比≥**2.0** + 收阳；-6%/15 日 | **001 第三阶段**：放量突破/试盘 | 量比阈值 2.0 比其他策略高，可作"放量"强阈值候选 |
| **MACD 金叉放量** `macd_golden`：金叉当日 + 量比≥1.5；-7%/20 日 | **001 三线金叉**中的 MACD 金叉 | 只覆盖三要件之一，需与均线金叉、量能金叉合并 |
| **均线多头** `bullish_alignment`：MA5>MA10>MA20>MA60 + 短期动量为正；-6%/20 日 | **002/趋势环境**：均线多头排列 | 作为"环境过滤"（多头市场才做右侧） |
| **布林突破** `boll_breakout`：破布林**上轨** + 量比≥1.5；-6%/15 日 | 001：布林**下轨→中轨**修复 | 位置不同：它是强势破上轨，操盘手是下轨向中轨修复，勿混用 |
| **放量创 60 日新高** `breakout_new_high_60d`：破前 60 日高 + 量比≥1.3 + 涨≥2%；-7%/20 日 | 002 右侧强度确认 | 趋势强度确认要件 |
| **高换手拉升** `high_turnover_surge`：换手 >5% + 涨 >3%；-5%/10 日 | 资金活跃（短线） | **谨慎**：中低频价值+形态定位下，高换手常是出货/情绪顶，003 阶段可能反向，不直接借 |

**003 六层价值过滤，这些技术策略基本帮不上**：003 是基本面/商誉/业绩雷/排雷门槛，靠我们的财务因子（`data/raw/fundamentals/`）+ R1/R3 实现；tickflow 的财务数据（fuyao 同花顺）在付费档，不接。

## 4. 可直接借的 Polars 指标写法（指标层）

来源：`backend/app/indicators/pipeline.py`（仅提炼一行表达式写法，未拷贝代码段）。

- **分组滚动均线（一条表达式算全市场）**：`pl.col("close").rolling_mean(20).over("symbol").alias("ma20")`；配合 `df.sort(["symbol","date"])`。EMA 用 `ewm_mean`，布林用 `rolling_std`，60 日高低用 `rolling_max/min`。
- **量比的"标准分母"口径（直接回应 I7 待校准项）**：
  `量比 = 当日成交量 / 前 5 个交易日平均成交量（不含当日）`
  Polars 形如 `pl.col("volume") / pl.col("volume").shift(1).rolling_mean(5).over("symbol")`；源码注释明确分母取 `volume.shift(1).rolling_mean(5)`（不含当天）。
  → 与操盘手用通达信对照时，这是明确的**盘后量比候选口径**（通达信盘中量比还含"当日已交易时长折算"，盘后全日口径与此接近），可解 I7 口径之争。
- **前复权**：复权因子按 symbol 累乘 `cum_prod().over("symbol")`（我们 baostock 直接取前复权，仅作交叉校验思路）。
- **工程细节**：`parquet.py` 用 `pl.scan_parquet(..., missing_columns="insert", extra_columns="ignore")` 容忍列的增量演进；显式 schema（date=Date、OHLCV=Float64）。我们做扫描专用数据集时可照此固化类型。

## 5. 明确不借（防过度工程与范围蔓延）

- ❌ FastAPI / React / Docker / 桌面打包 / Web 面板（Q6 已定脚本+静态图；个人单机、不做 Web）。
- ❌ `matrix.py` 的 memmap 宽矩阵磁盘缓存、分区指纹、预热线程池等重型设施（为 Web 多用户实时刷新设计；我们日频盘后扫描，先简单实现，**基准证明不够快再考虑**）。
- ❌ tickflow.org 数据源与 fuyao（同花顺财务）/龙虎榜/实时等付费档；不替换 baostock、不整体挂读它的数据目录（schema/分区都不同，需适配层，不划算）。
- ❌ AI 策略生成器（`strategy/ai_generator.py`、`prompt_builder.py`，自然语言生成策略）：与我们"克隆操盘手明确规则、人定阈值"路线不同，远期再议。
- ❌ 涨停/连板/情绪类（`consecutive_limit_ups`、`near_limit_up`、`active_limit_gene` 等）：偏短线情绪，与中低频价值+形态定位不符，003 阶段甚至要排雷。
- ❌ **不直接采用任何默认阈值**：周期不匹配（它 10–20 日，操盘手月度/横盘数月），全部仅作 T30 校准候选。

## 6. 对 ADR-005 / 三引擎基准的输入

1. 基准必须在**我们"一只一文件"的自有 Parquet** 上实测，不能外推 tickflow"按日期分区"的性能。
2. 代表性负载（贴近 3 号池 v2）：
   - **L1 捞数/IO**：加载全市场最近 1–3 年日线成面板；
   - **L2 指标**：按 symbol 分组滚动算 MA5/10/20/60、量比（前5日均量）、60 日高低、布林；
   - **L3 形态时序**：平台振幅（前 N 日不含今日）+ 收盘破前高 + 量比阈值；均线粘合近 N 日持续；回踩不破前低；
   - **L4 横截面**：某交易日全市场按评分排序/粗筛出前 N。
3. 三种实现：**pandas**（现状基线）、**DuckDB**（SQL 窗口函数 + glob 就地查）、**Polars**（lazy + `.over("symbol")` + rolling）；记录耗时、峰值内存、代码行数/可读性。
4. 待基准回答的关键问题：
   - 我们一只一文件布局下，Polars/DuckDB 相对 pandas 逐只循环有无量级优势？
   - 复杂嵌套形态（"先 A 后 B、N 日内、不创新低"）用 Polars 表达式 / DuckDB SQL / numpy 矩阵哪种最可读、可维护？
   - 是否值得派生一份"全市场长表（可按年/按日分区）"扫描专用 Parquet（原始一只一文件继续作底稿）？
