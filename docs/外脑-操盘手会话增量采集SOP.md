# 外脑 · 操盘手会话增量采集 SOP（A 方案）

> 目的：自动发现操盘手（nero6688/大海星）在**其它豆包工作任务窗口**里聊的行情、复盘、操作，
> 增量收集 → 去重 → 归档编号 → 提炼可结构化判断，持续喂养外脑。
> 配套脚本：`scripts/scan_operator_sessions.py`（纯标准库，系统 `python3` 可跑）。

---

## 1. 覆盖边界（先读，避免误用）

| 数据源 | 是否覆盖 | 说明 |
|---|---|---|
| 豆包 **agent 工作任务**会话（本桌面端、工作模式） | ✅ 覆盖 | 逐字落盘到本机 `.sessions/*/trajectory.jsonl`，脚本扫的就是它 |
| 豆包 **2.1 Pro 普通对话**（聊天窗口，右下角标"豆包 2.1 Pro"） | ❌ 不覆盖 | 正文存云端、**不落地本机**（已解包 IndexedDB 验证，关键词零命中）。要收这类，走会话分享链接 `doubao.com/thread/<id>` 人工/浏览器读取 |
| 微信沟通、公众号文章 | 另一套 | 用 `wechat-control` 技能只读库（见 AGENTS.md §1） |

**机器边界（重要）**：trajectory 只在"产生该会话的那台机器"本地落盘、**不跨机同步**。
操盘手在他自己电脑上聊的任务窗口，本脚本必须在**他那台机器**、同仓库下运行；
开发机上只能扫到开发机自己的会话。脚本路径与仓库无关、可直接随仓拷贝。

---

## 2. 它怎么工作（增量原理）

- 扫描所有 Profile 下的主对话 trajectory（`m_` 开头；跳过子 agent `s_/o_`、跳过 tool 行）。
- **游标**：`data/operator_recall/state.json` 记录每个会话已处理到的 jsonl 行号；下次只读新增行，绝不从头重扫。
- **命中**：新增文本命中操盘关键词（确定强词 1 个，或弱词 ≥3；"建仓"为歧义词不单独触发，详见脚本词表）。
- **暂存**：命中会话的新增 user/assistant 原文追加到 `data/operator_recall/inbox/<sid>_<标题>.md`，按批次带行号。
- **排除当前会话**：默认跳过最新（正在运行本任务）的窗口；`--include-current` 可关。
- `state.json` 与 `inbox/` 都在 `data/`（已 gitignore，**本机本地、不入仓**）。

## 3. 首次部署（在"有操盘手会话的机器"上做一次）

```bash
cd <astock-quant 仓库根>
python3 scripts/scan_operator_sessions.py --baseline   # 把现有历史全部标记为已读，不导出
```

> 为什么先 baseline：`09_调研底稿与素材/操盘手经验/` 已手工归档过历史素材（编号到 125）。
> baseline 后只报"今后新产生"的内容，避免把已整理过的历史再倒一遍。
> 若想回补某个特定历史会话，用 `--rescan <sid后几位>` 单独导出，人工比对是否已归档。

## 4. 日常触发（记忆机制，不挂定时）

本任务**不设 cron**，靠 AGENTS.md 里的记忆规则在合适时机被触发。出现以下任一情况即跑一次：

- 新会话/新窗口接手本仓（执行 AGENTS.md「新会话恢复顺序」时顺带跑）；
- 用户提到"操盘手/大海星/nero 今天复盘了吗""他在别的窗口聊了行情""扫一下他的会话"；
- 准备更新外脑档案、参与者画像、操盘手经验目录之前；
- 操盘手当天/近期可能在别的任务窗口做了 A 股复盘。

```bash
python3 scripts/scan_operator_sessions.py             # 增量扫描
python3 scripts/scan_operator_sessions.py --dry-run   # 只看会命中什么，不写暂存、不推进游标
```

脚本只负责"发现候选 + 取原文"，**是否真为操盘观点、怎么归档，由 AI 审阅决定**（见第 5 节）。

---

## 5. 标准处理流程（扫描之后）

1. **看报告**：终端列出本次新命中的会话（sid、标题、行范围、命中词）。
2. **审阅 inbox**：打开 `data/operator_recall/inbox/<sid>_*.md`，判断：
   - 是操盘手的**行情复盘/交易观点/操作记录** → 进归档；
   - 是**项目复盘/开发讨论/资料整理**（关键词误召回，如"建仓库"被识别成"建仓"、"项目复盘"）→ 不归档，仅游标已推进即可；
   - 一条会话里只有部分是观点 → 只摘相关段落。
3. **归档编号**：在 `09_调研底稿与素材/操盘手经验/` 新建
   `NNN_<豆包threadid或sid>_<标题> - 豆包.md`，编号在当前最大号上**顺延**（截至本 SOP 为 125，新文件从 **126** 起）。
   正文沿用既有样板：顶部"来源头"（来源=豆包任务窗口、sid/thread、日期、操盘手），其下干净正文。
4. **提炼结构化判断**：每份复盘额外抽取下列字段（补在文首"结构化摘要"或登记到外脑档案）：
   - 日期/交易日；
   - 指数与涨跌（上证/深成/创业板/科创50/沪深300/北证，收盘价、涨跌幅）；
   - 量能情绪（成交额、放量/缩量、上涨下跌家数、涨停跌停）；
   - 板块（领涨/领跌、轮动）；
   - 驱动因素（政策/消息/资金，注明"市场归因，待官方证实"）；
   - **操盘手观点与操作**（看多/看空、建仓/加减仓、股票池、仓位、止盈止损、关注标的）；
   - 风格信号（左侧/右侧、困境反转/底部突破、情绪判断）。
5. **去重核对**：归档前在 `09_调研底稿与素材/操盘手经验/` 按标题/日期/sid 检索，确认没有同内容旧档；
   同一批会话已在别的机器归档过则不重复建（跨机去重以 09 目录的归档 md 为准）。
6. **回写**：归档完成后，把编号记到 `state.json` 对应会话的 `archived` 列表（手工或后续脚本补）。
7. 提炼结果按价值同步更新 `docs/参与者画像.md`、操盘手经验目录索引，因子相关结论供量子系统参考。

---

## 6. 去重的三层防线

1. **游标**：行号级，不重复读同一行（`state.json.processed_lines`）。
2. **inbox 批次**：一个会话一个文件，每批带行号区间，不重复段落。
3. **归档对照**：正式落 09 前与既有归档 md 按 sid/标题/日期比对——这一层防跨机、防历史重复。

---

## 7. 隐私红线

- `data/operator_recall/`（state + inbox 原文）**只在本机、已 gitignore，绝不入 git、不外发**。
- 归档进 09（本仓为 public）的只能是**操盘手观点/复盘正文**；剔除系统提示、工具返回、token、密钥、
  第三方隐私、与交易无关的私人内容。拿不准是否敏感就不入库。
- 不在仓库、提交信息、对外文档里出现账号口令、Cookie、Authorization。

---

## 8. 词表与噪音维护（召回不准时调）

词表在 `scripts/scan_operator_sessions.py` 顶部：

- `STRONG_KW`：确定强词（复盘/A股/大盘/持仓/买入/涨停/板块轮动…），命中 1 个即候选。
- `AMBIGUOUS_REGEX`：歧义词（"建仓"），**不单独触发**，因 git 语境"建仓库"会简称"建仓"。
- `WEAK_KW`：弱词（股票/行情/板块/基金/ETF/量化…），需 ≥3 个才候选。
- `NOISE_KW`：首条用户消息命中即跳过的噪音会话（微信采集/高顿/CPA/爬虫/珠宝/网盘/仓库…）。

调参原则：**召回宁全勿漏**，少量假阳性由第 5 步 AI 审阅过滤；只有某类误报大量出现才加词/收紧阈值，
改动后用 `--dry-run` 对照命中清单验证，别为消噪漏掉真复盘。

## 10. 故障排查

| 现象 | 原因/处理 |
|---|---|
| 扫不到操盘手在他机器上的会话 | 脚本必须在**他那台机器**跑；trajectory 不跨机同步 |
| 普通对话（豆包2.1 Pro）扫不到 | 设计如此，正文在云端；改用 `doubao.com/thread/<id>` 分享链接读取 |
| 提示"未发现任何主会话" | 该机器没用桌面端工作模式产生过任务；先正常用一次 |
| 命中一堆开发会话 | 先确认标题是否被 `NOISE_KW` 覆盖；git"建仓"已作歧义词；其余靠 AI 审阅 |
| 想重新基线对齐 | 删 `data/operator_recall/state.json` 后重新 `--baseline`（inbox 需另行清理） |
| 游标疑似错位 | `--rescan <sid>` 全量重导该会话，人工核对后归档 |
