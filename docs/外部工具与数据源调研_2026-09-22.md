## 二、逐对象详评

### 2.1 KHQUANT

#### 精确定位

"KHQUANT"重名，检索出两个完全不同的项目：

| 候选 | 身份 | 判定 |
|---|---|---|
| **A. 看海 khQuant（OSkhQuant）** | GitHub `khscience/OSkhQuant`，官网 khsci.com/khQuant，作者 Mr.看海 | 与A股量化强相关，基于 MiniQMT 的 Windows 桌面回测平台 |
| **B. Khy-quant** | PyPI `Khy-quant`，GitHub `khyquant/khy-quant`，官网 khyquant.top，作者 孔浩原 | 名义上是A股量化系统，实际是学生毕业论文交付包，包装痕迹重 |

> 两者名字都含"kh"，A是"看海"拼音首字母，B是作者姓名缩写（Kong Haoyuan）。

#### 候选 A：看海 khQuant（OSkhQuant）

- **核心能力**：基于券商 MiniQMT（迅投 xtquant）的本地回测/模拟盘 GUI 平台（PyQt5）；V3 版新增 CLI 工具 `kh`，支持数据下载（xtdata/BaoStock/Tushare → 本地 DuckDB）、`.kh` 配置文件一键回测；定位A股中低频因子选股、轮动、事件驱动、网格T0。
- **数据覆盖与口径**：行情深度依赖券商 MiniQMT 客户端；Tick 仅最近约1个月、1/5分钟K线仅最近约1年（**比 baostock 的2020-01起点更短**）；支持前复权；退市股未提及；官方建议单次订阅≤50只。
- **免费与许可**：官方自述"完全开源免费"，但许可证实际是 **CC BY-NC 4.0**（非OSI认证，禁止商业用途）；商业模式=作者推荐渠道开户返佣+打赏。
- **平台硬伤**：官方教程明确"**关于 macOS：目前完全不支持**"，主开发/测试环境为 Windows 10+ 64位。
- **活跃度**：约859 stars（git-stars.org 2026-01快照，未能实时复核）；最新稳定版 v3.4（2026-08）；单人维护。

**对两条主线的用处**：
- 量子系统：**基本无关**。macOS不支持是硬伤；架构（MiniQMT客户端绑定）与本项目（baostock+pandas+DuckDB）完全不同；数据深度不如baostock；无内置指标函数（需自引TA-Lib）。
- 外脑3号池扫描器：**无关**。不提供现成量比/TRIX/困境反转面板。
- **唯一可借鉴点**："本地 DuckDB + `.kh` 声明式配置 + CLI 一键回测"设计思路，与本项目已有 DuckDB 只读架构理念相近，可作为配置文件格式/CLI 命令组织的参考样本。

#### 候选 B：Khy-quant

- PyPI 元数据自称"面向中国A股的智能量化交易系统"，但最新1.8.0（2026-05-13）项目描述已缩回"毕业论文项目：螺纹钢期货策略分析"。
- **高风险信号**：①许可证 MIT→Proprietary 矛盾；②官网域名仅5个月且被 ScamAdviser 标记"网站可能存在风险"；③11天内连发26个版本的异常迭代；④QQ群引流；⑤作者无其他可信量化项目记录。
- **结论**：无任何可用价值，直接忽略。

#### 建议动作

- 看海 khQuant：**观察（仅文档层面），不跑探针**。macOS硬不支持+CC BY-NC非商业+数据深度不如baostock+无现成指标面板。仅可阅读其 CLI/DuckDB 设计文档作架构参考。
- Khy-quant：**高风险/直接忽略**。

### 2.3 tickflow-stock-panel（TSP）

#### 精确定位

| 项 | 结论 |
|---|---|
| GitHub | **`shy3130/tick-stock-panel`**（仓库已于2026年6-9月间从`tickflow-stock-panel`更名，旧URL自动重定向） |
| 官网/数据源 | tickflow.org（数据源产品站）、docs.tickflow.org（API文档） |
| PyPI | `tickflow` 0.1.25（这是**数据源SDK**，不是面板本体；面板是独立Docker应用） |
| 性质 | 个人开源，**非TickFlow官方产品**（作者自述"TickFlow数据源+个人工作台"，README带推荐码） |

#### 核心能力

TSP 不是单一"指标库"或"看盘面板"，而是一个**自托管完整量化工作台**：

1. **选股引擎（Screener）**：25个内置策略，Polars向量化"毫秒级扫全A"，日线/分钟策略统一单池。
2. **指标流水线**：68列指标与信号，一次扫表落盘 enriched Parquet。
3. **回测引擎**：基于 vectorbt，支持因子回测（IC/IR/分层收益/多空）、策略回测（净值/夏普/回撤/胜率/蒙卡）、分钟策略回测、参数敏感性与滚动样本外。
4. **因子平台**：DSL自定义因子（25算子）、Newey-West检验、BH-FDR q值、因子↔策略双向联动。
5. **监控中心**：策略/个股信号/价格/全市场异动四类规则，AND/OR+冷却去重，弹窗+语音+飞书/企微/邮件/Webhook推送。
6. **异动监控**：竞价异动、盘中异动（涨停/炸板/新高/放量）、偏移异动。
7. **板块与情绪**：概念/行业涨幅轮动（ths维度RPS）、市场情绪6阶段（冰点/启动/主升/高潮/退潮/修复）、连板梯队。
8. **AI助手（可选）**：18个只读工具的对话式数据问答、自然语言生成策略、盘后AI复盘；不配置Key则关闭。
9. **数据扩展**：第三方数据通过HTTP定时拉取/CSV上传/JSON写入并入DuckDB。

#### 技术栈与数据接口

| 层 | 选型 |
|---|---|
| 后端 | Python 3.11+ / FastAPI / Pydantic v2 / APScheduler |
| 计算 | **Polars**（向量化指标与选股） |
| 存储 | **Parquet分区表 + DuckDB（查询）+ JSON按日缓存** |
| 回测 | vectorbt + 自研仓位模拟引擎 |
| 前端 | React 18 / TypeScript / Vite / ECharts / Lightweight Charts |
| 部署 | Docker单容器（GHCR镜像，arm64/amd64） |

**能否对接本项目现有的 Parquet/DuckDB？**
- 不能直接挂载读取现有 `data/parquet` 目录（TSP有自己的数据目录结构）。
- 但支持三种外部数据并入路径：①CSV/Excel页面上传；②HTTP定时拉取（需写一个轻量本地FastAPI适配器暴露DuckDB/Parquet）；③JSON程序化写入。
- 扩展表数值字段自动注册为因子列，可直接进信号条件和因子库。

**结论**：技术栈与本项目（Python + Parquet + DuckDB）**同代且高度重合**，这是它和其他面板最大的区别。但对接不是"读同一个文件夹"，而是要写一个适配层。

#### 免费与许可

- **许可证**：MIT（真开源、可自托管、二次开发）。
- **面板本身**：完全免费、开源、可自托管。
- **数据分层付费**（关键风险点）：
  - **Free（免费，无需注册）**：仅历史日K+标的信息。无实时、无分钟线、无除权因子。
  - **Starter**：标的池批量查询、除权因子。
  - **Pro**：分钟K线（约一年历史）、日内分时、五档盘口。
  - **Expert**：全市场盘中1分钟增量落盘。
  - **fuyao（同花顺REST）**：财务四表、龙虎榜、盘前风向标——需自备API Key（付费）。
  - **AI功能**：需自备OpenAI兼容Key，不配置则关闭。
- **结论**：面板免费，但**真正有价值的深度数据（分钟线/财务/龙虎榜/实时）都在付费档**。免费档只能跑日K选股+回测的最小闭环。

| **量比=VOL/HHV(VOL,60)** | 有"量比"（A股标准口径：当日量/过去5日均量）和"量均线"，但不是60日高点成交量口径。Polars表达式写`vol / vol.rolling(60).max()`一行即可。 | 🟡 口径不同但可借鉴实现模式 |
| **TRIX(12,9)** | 68列指标清单列了MA/EMA/MACD/RSI/KDJ/ATR/布林/量比，**未列TRIX**。 | 🔴 内置没有，但Polars三重EMA实现TRIX很简单 |
| **左侧困境反转** | 有"超跌反弹""超卖反转""新低反转""MACD零下回升""长下影反击" | 🟢 可直接参考Polars写法 |

| **流通市值<200亿** | 市值字段未在核心指标清单明确，可通过扩展表上传 | 🟡 需自己喂市值数据 |

**最有价值的借鉴点——策略文件结构**：TSP的每个策略`.py`包含：
- `basic_filter(df, params)`：单日截面过滤，返回`pl.Expr`
- `filter_history(df, params)`：历史窗口过滤，配合`LOOKBACK_DAYS`参数
- `ENTRY_SIGNALS` / `EXIT_SIGNALS`：进出场信号列

**这个`filter_history + LOOKBACK_DAYS + 进出场信号列`的设计，正好解决本项目3号池v1"缺形态确认与时序逻辑"的痛点**（I12）。当前v1是自研Python脚本，形态确认和时序逻辑（如"先缩量回调3天再放量突破"）可以直接参考TSP的Polars表达式向量化模式重写，而不是用pandas逐日循环。

#### 接入工作量评估

#### 候选A：shiyu-coder/Kronos —— 金融K线开源基础模型

**核心能力（官方自述，README+论文arXiv:2508.02739）**
- 首个专为金融K线（OHLCV）设计的decoder-only基础模型；两阶段：专用tokenizer把连续OHLCV量化为分层离散token → 自回归Transformer在token上做next-token prediction。
- 预训练数据：全球**45+交易所、120亿+条K线、7种采样频率**（含上交所/深交所）。
- 任务覆盖：价格预测、收益预测、波动率预测、合成K线生成、投资模拟；论文称在金融基准上RankIC比通用TSFM高93%。
- 输入只需一个pandas DataFrame，列含`open/high/low/close`，`volume/amount`可选；输出未来N根K线的OHLCV+量额，并支持`sample_count`条概率路径。

**模型规格**

| 模型 | 参数量 | 上下文长度 | 是否开源 |
|---|---|---|---|
| Kronos-mini | 4.1M | 2048 | ✅ |
| Kronos-small | 24.7M | 512 | ✅ |
| Kronos-base | 102.3M | 512 | ✅ |
| Kronos-large | 499.2M | 512 | ❌ 未开源 |

**技术栈**：Python 3.10+、PyTorch；推理用`KronosPredictor`；微调脚本基于**Qlib**（`pyqlib`）。

**关键事实（GitHub API实测，2026-09-22）**
- ⭐ **39,337 stars** / 6,553 forks / 277 open issues / 67 open PRs
- 创建于2025-07-01；**最近一次代码push：2026-04-13**（距今约5个月无新commit，活跃度中等偏冷）
- 许可证：**MIT**（真开源、可商用、可自托管、无Key、无付费墙）

**数据覆盖与口径（重要）**

**免费与自托管**：完全免费、MIT、权重挂HuggingFace（国内需镜像下载）、可本地跑。无付费版、无荐股群、无带单——**这是学术开源项目，不是营销产品**。但第三方对其实际效果评价分化：36氪报道"多数使用者对输出结果表示不满"；中金财富研报则做了A股指数择时应用实验。

## 五、总体结论

### 5.1 5个对象的价值排序

1. **tickflow-stock-panel（最有价值）**：MIT开源、4691star、Polars+Parquet+DuckDB栈与本项目高度重合，25个内置策略的Polars写法可直接借鉴来重构3号池扫描器的形态确认与时序逻辑（I12）。**只读代码借鉴，不整体部署。**
2. **public-apis（部分有用）**：48.2万star的API索引，但金融分类对A股几乎没有新弹药。唯一值得跑探针的是Alpha Vantage（25次/天，够给3号池观察名单做TRIX等技术指标校验）。T31/T32在这份清单里完全没有免费解。
3. **kronos（观察，远期实验性）**：清华系金融K线基础模型，MIT开源3.9万star，但不是数据源、不解决任何数据/工程缺口。仅可在外脑线作为3号池候选股的实验性"AI打分器"因子，且Mac单机只能跑small模型、不接模拟盘。
4. **KHQUANT（观察，仅文档参考）**：看海khQuant是Windows-only的MiniQMT平台，macOS硬不支持、CC BY-NC非商业、数据深度不如baostock、无内置指标面板。仅其CLI/DuckDB设计思路可作架构参考。Khy-quant是高风险论文包装，直接忽略。
5. **灵汐AI（高风险，直接拉黑）**：抖音版无官网/无主体/无开源/已出现在反诈标签下；正规券商版全部触红线（闭源终端/开户/自动下单）。无任何可用价值。
