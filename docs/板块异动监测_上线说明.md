# 盘中板块异动实时监测 · 上线说明（v1）

> 对应需求：2026-09-24 收市前「海峡两岸概念」突发，要求盘中实时监控全板块、主动微信推送。
> 方案对比见 `盘中板块异动监测方案_AB双轨_v1.0.md`；本文件只记"代码怎么跑、踩过什么坑"。

## 1. 它干什么

盘中（9:30–11:30 / 13:00–15:00）每 60 秒（14:30 后 30 秒）扫一遍**全部概念+行业板块**，
命中两级触发就微信推送，并自动留痕供盘后复盘。

- **L1 异动**（满足任一）：板块涨速 ≥1.5%（尾盘 5min≥1%）；或 涨幅>2.5% 且 涨停≥3。
- **L2 主线**（同时满足）：涨幅>2.5% 且 涨停≥5 且 量比≥1.5（可得时）。
- **状态机去重**：每板块每级当天只推一次，L1 升级 L2 再推；条件消失后重新放量可再推 L1，L2 当天不重复。

## 2. 数据源（实测定稿，2026-09-24）

| 用途 | 来源 | 取法 | 实测结论 |
|---|---|---|---|
| 板块涨幅/量比/涨速 | 东财 push2 | **curl 子进程**直连 | AkShare 封装用 requests 会被东财关连接；curl 放行。高频会被东财限流（Empty reply），需降级 |
| 涨速/量比/资金流（个股） | 腾讯 | AkShare `stock_zh_a_spot_tx` | **抗封，盘中高频主力**，直接给 speed/lb/zljlr |
| 涨停家数/连板/行业 | 东财 datacenter | AkShare `stock_zt_pool_em` | 稳定；自带"所属行业"，无"所属概念" |
| 板块行情备份 | 新浪 | AkShare `stock_sector_spot` | 东财被限时降级，无涨停/量比 |

> **关键坑**：东财 push2 对 Python requests 的 TLS 指纹直接断连，但 curl 可通；
> 所以板块快照一律走 curl（脚本里 `_curl`）。东财限流时整路失败、自动切新浪，不崩。

## 3. 文件与部署

- 脚本：`scripts/intraday_sector_monitor.py`
  - 试跑：`.venv/bin/python scripts/intraday_sector_monitor.py --once`（扫一轮即退）
  - 构建映射：`--build-map`
- 常驻服务 plist：`~/Library/LaunchAgents/com.astock-quant.intraday-monitor.plist`
  - 加载：`launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.astock-quant.intraday-monitor.plist`
  - 停止：`launchctl bootout gui/$(id -u)/com.astock-quant.intraday-monitor`
  - 单例：脚本内 fcntl 文件锁，重复启动自动退出；KeepAlive 崩了自拉起。
- 持仓联动：`config/holdings.csv`（无持仓留空即可）。
- 留痕：`data/intraday_alerts/YYYY-MM-DD.csv`（不入库）。
- 日志：`data/_workspace/intraday_monitor.log`、`intraday_launchd.err.log`。

## 4. 推送凭证（当前缺口，缺了只本地留痕不推送）

在 plist 的 `EnvironmentVariables` 二选一改：
- `WECOM_BOT_WEBHOOK`：企业微信群机器人 webhook；或
- `SERVERCHAN_KEY`：Server酱 SendKey。

改完重新 bootstrap。**不要把 webhook/key 写进入库文件。**

## 5. 当前局限（已知，待迭代）

- 持仓/候选联动目前只按板块名粗标，未按成分精配；腾讯 speed/lb 聚合成板块的计算 v1 未启用（等东财恢复后用板块自带字段为主）。
- 概念板块涨停归集依赖"板块→成分"映射；东财被限当天映射可能不全，行业板块（涨停池自带行业）不受影响。
- 免费 L1 3 秒一帧，轮询 60s 内推送；要逐笔毫秒才需付费 Level-2。

## 6. 历史预警留存与查询

每条触发的预警自动追加到 `data/intraday_alerts/YYYY-MM-DD.csv`（按日一个文件，**不入库**），字段含时间/级别/板块名/涨幅/涨停数/量比/**阈值快照**/完整消息。

- **为什么存"阈值快照"**：阈值以后会调（`MON_CHG_L1` 等环境变量），每条记录自带当时生效的标准（如 `chg>2.5%|ztL1>=3|ztL2>=5|lb>=1.5`），日后复盘不会对不上账。
- **查询**（在项目根目录）：
  - 全部：`.venv/bin/python scripts/query_alerts.py`
  - 某天：`--date 2026-09-25`
  - 某级别：`--level L2`
  - 板块名搜：`--board 海峡`
- 阈值改动后重启常驻服务才生效；当天进程内阈值固定，当日所有预警用的是同一套快照。
