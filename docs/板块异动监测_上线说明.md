## 1. 它干什么

交易时段（9:30–11:30 / 13:00–15:00，已接 A 股交易日历，周末与法定节假日自动休眠）周期性扫描**全部概念 + 行业板块**，命中两级信号就推送企业微信群，并全程留痕供复盘。

- **🟠 L1 异动预警**（满足任一）：板块 10 分钟涨速 ≥ 阈值；或 板块涨幅 > 阈值 **且** 涨停家数 ≥ L1 门槛。
- **🔴 L2 主线确认**（同时满足）：涨幅 > 阈值 且 涨停家数 ≥ L2 门槛，且量比、上涨家数占比同时达标（量比字段拿不到时宽松放行，宁可多报不漏报）。
- **走强/主线提示**（不单独轰炸）：活跃波内涨停数再上台阶才追加"走强一步"；板块涨停占全市场涨停比例 ≥ 集中度阈值且为本轮首次时标"⭐首次成为市场主线"。
- **分级去重 + 波次管理**：同一板块当天每级只推一次、L1 升 L2 再推；短暂掉出阈值给**消退宽限期**，期内抖动静默；彻底消退后再次放量才算"新一波"，消息标注**今日第几次 / 第几波 / 距上次多少分钟**。

## 2. 代码结构（2026-10-12 起：分层包 + 薄入口）

业务逻辑全部在 `src/monitor/` 包内，`scripts/intraday_sector_monitor.py` 只是约 20 行的**薄入口**（把项目根加入 `sys.path` 后 `from src.monitor.cli import main`）。判定与文案是**无 IO 纯函数**（同样输入必得同样输出，离线可大批量回归）；网络/读写文件/发消息等副作用集中在数据源、落盘、推送三个模块。

| 模块 | 职责（依赖方向只允许从上到下） |
|---|---|
| `cli.py` | 入口、轮询调度、时间档（常态/尾盘/休市）、看门狗、停机补检 |
| `monitor.py` | 只做编排：逐板块判定、决定是否推送 |
| `reconcile.py` | 东财 / 腾讯 双源口径对账（服务 I14） |
| `notifier.py` | 企业微信群机器人 / Server 酱推送与**回执** |
| `persistence.py` | 告警、快照、停机状态、板块状态读写落盘 |
| `statemachine.py` | 板块状态机：分级、消退宽限、波次、原因标签、文案（纯逻辑） |
| `aggregator.py` | 腾讯个股行情聚合成板块维度、涨停判定（**I16 修复点**） |
| `datasources.py` | 东财 / 腾讯 / 新浪数据采集与降级、成分映射、交易日历 |
| `codes.py` | 股票代码归一化（**I16 修复点：920 归 bj**） |
| `config.py` | 全部阈值与路径（最底层，`MON_` 环境变量可覆盖） |

- 分层契约写在 `pyproject.toml`（import-linter 校验，违规/循环依赖必须为 0）。
- 测试在 `tests/monitor/`（测试代码量 > 业务代码）；关卡映射在 `quality-gates/tools/python.yaml`。

## 4. 数据源与降级链（当前实现，不依赖同花顺）

| 用途 | 主用 | 兜底 / 备份 | 取法与坑 |
|---|---|---|---|
| 板块涨幅 / 量比 / 涨速 / 成交额 | **东财 push2 板块快照**（概念 + 行业） | 腾讯个股聚合 → 新浪板块 | 东财对 Python `requests` 的 TLS 指纹直接断连，**必须用 `curl` 子进程**（`em_boards`）；高频会被限流（约 30–60 分钟自解），失败自动降级、不崩 |
| 个股涨速 / 量比 / 涨跌幅 / 资金流 | 腾讯全市场个股快照 `stock_zh_a_spot_tx`（约 5500+ 只，抗封） | — | 数值列是字符串，比较前必须 `to_numeric`；东财被限时用它按成分**自行聚合**成板块维度（`tx_board_agg`） |
| 涨停家数 / 连板 / 所属行业 | 东财涨停池 `stock_zt_pool_em`（datacenter，不被 push2 限流） | 腾讯个股按涨幅判定 | 涨停池自带"所属行业"、无"所属概念" |
| 板块行情 / 成分映射备份 | 新浪 `stock_sector_spot` / `stock_sector_detail` | — | 板块粗、漏小概念，仅兜底 |
| 板块→成分股映射 | 盘前 09:13 任务预建、当日缓存 `sector_map_YYYYMMDD.json`；东财成分优先、新浪兜底；**盘中缺缓存先用最近交易日历史映射、后台单飞（single-flight）重建，不阻塞开盘** | 历史交易日映射兜底 | 成分日变极小；只守行业完整性（行业缺失或不足 100 只必补新浪），概念不强制；建成后行业覆盖不足打健康告警 |

**涨停判定口径（I16 修复后，务必注意）**
- 主板 10cm：涨幅 ≥ 9.9% 计涨停；创业板（30）、科创板（68）、北交所（8/4/92 开头）20cm：涨幅 ≥ 19.9% 计涨停。
- 腾讯返回的代码**带市场前缀**（如 `sz300308`、`sh688808`、`bj830xxx`），判定前先剥掉 `sh/sz/bj` 前缀回到 6 位裸码再分桶——否则 20cm 票只涨 9.9% 会被误计涨停、板块涨停数虚高（I16，已修）。
- 北交所 **920 新号段**归一化时优先归 `bj`（不能被 `"9"` 规则抢先归成 `sh`，I16 已修）。
- 已知简化 **I17（低优先）**：北交所实际涨跌停为 **30%**，当前与创业/科创同按 20cm（19.9%）桶处理；影响面仅"腾讯兜底 + 板块含北交成分"，随 I14 一并评估。

## 5. 状态机与推送语义（防刷屏 / 防失忆）

- 状态：每板块 `NONE → L1 → L2`，当天每级只推一次，L1 升 L2 再推一次。
- **消退宽限**：板块掉出阈值后进入宽限（默认 10 分钟），期间反复达标**静默**（治压线抖动造成的重复推送）；宽限满仍不达标才结算本波；之后再度放量算**新一波**。
- **波次与原因标签**：消息固定标注 `首次启动` / `升级 L1→L2` / `走强一步` / `首次成为市场主线` / `再度启动·第W波`，并带"今日第 N 次、第 W 波、距上次 N 分钟、消退期最低涨幅"。跨波不做台阶式对比，避免拿上一波峰值误报"走弱"。
- **状态持久化**：板块状态落 `data/_workspace/board_states_YYYY-MM-DD.json`，重启读回——**重启不再把"一直达标"的板块误当新启动**（治 I15）。
- **兜底口径标注**：东财被限流、本轮改用腾讯等权聚合（或新浪）兜底算出的信号，推送消息指标行后会自动加一行 ⚠️ 提示——腾讯注明"等权口径、与东财加权在临界值附近可能有出入"，新浪注明"缺涨停/量比维度、信号可能不完整"；东财正常时无此行。避免把限流日的兜底信号当成与平时同口径的结论；I14 验收、腾讯口径固化后可评估去留。

## 6. 可靠性：防静默三道 + 推送回执 + 双源对账

1. **每轮全板块快照**落 `data/_workspace/snapshots/YYYY-MM-DD.csv`，可逐分钟复盘任意时刻到底看到了什么。
2. **启动自检**：交易时段首轮若所有数据源不可用或即抛异常，立即高声量企微告警。
3. **盘中心跳看门狗**：连续 `MON_HB_STALL_SEC`（默认 30 分钟）无成功扫描即告警，同一次宕机冷却防刷屏，恢复后推"✅已恢复"；休市不误报。
4. **推送回执**：读取企业微信返回的 `errcode/errmsg`，成功打"发送成功（errcode=0, HTTP200）"、失败打返回码——发没发得出去有据可查。
5. **双源对账（I14，纯观测不改触发）**：东财可用时每 `MON_RECONCILE_INTERVAL_SEC` 采一次东财/腾讯同时点对照，落 `data/_workspace/source_diff/YYYY-MM-DD.csv`。用于判定腾讯等权聚合能否长期替代东财加权指数：判据为"≥95% 板块涨幅差 ≤0.3 个百分点、临界带跨阈值分歧率 ≤2%"，达标则腾讯可独立，否则腾讯聚合改流通市值加权。当前观测中。

## 8. 部署与运维

- **launchd 任务（两个，权威清单/部署/停用命令见 `scripts/launchd/README.md`）**：
  - `com.astock-quant.intraday-monitor`：盘中常驻，`RunAtLoad` + `KeepAlive`（崩了/开机登录后自动拉起，已实测关机重启后自恢复），fcntl 锁保证单例；板块状态当日持久化、重启不重复推送。
  - `com.astock-quant.build-sector-map`：盘前周一至五 09:13 定时跑 `--build-map` 预建当日板块映射，避免开盘后现抓拖慢首战（plist 仅在本机、无 webhook）。
- 加载：`launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.astock-quant.intraday-monitor.plist`
- 卸载：`launchctl bootout gui/$(id -u)/com.astock-quant.intraday-monitor`
- 重启（改代码/改阈值后）：`launchctl kickstart -k gui/$(id -u)/com.astock-quant.intraday-monitor`
- 手动试跑：`.venv/bin/python scripts/intraday_sector_monitor.py --once`（**强制扫一轮，不分时段**；终端无 webhook 时为"仅留痕不推送"）；只建成分映射：`--build-map`。
- **盘中红线**：交易时段（9:30–11:30 / 13:00–15:00）**禁止改 `scripts/`、`src/monitor/` 或重启服务**；需要重启只在 **11:30–13:00 午休或 15:00 收盘后**。
- **部署门禁**：上线脚本先备份→替换→字节比对→编译→跑离线状态机场景回归（含多波次/重启/阈值快照），任一失败自动 `git checkout` 回滚上一版，全过才重启。
- **单点边界（如实告知）**：监控与看门狗同在这台 Mac，若**交易时段内**电脑关机/休眠，关机当时无法告警（看门狗自己也停了）；开机/联网后 launchd 自拉起并做停机补检。收盘后关机不影响当日推送。
- **网络代理（I18 坑，已修）**：本机开 macOS 系统代理（HTTP/HTTPS/SOCKS）时，akshare 走 `requests` 会被代理劫持报 `ProxyError`（注意东财 push2 主行情走 `curl` 子进程、不读 GUI 系统代理，故未受影响）；`config.py` 已在清代理 env 后强制 `no_proxy=*`/`NO_PROXY=*` 直连国内源，改采集代码时不得让它重新读系统代理。
