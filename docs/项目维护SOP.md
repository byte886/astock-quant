# 项目维护 SOP · 沉淀收拢 / 维护节奏 / 文档体检 / 冷启动验收

> 文档类型：SOP（标准作业流程，给每个接手本仓的 AI/人）
> 更新频率：流程变化时；配套脚本 `scripts/doc_health_check.py`
> 目的（一句话）：**任何一个新窗口只拿到仓库路径，就能知道"这是什么、现在在哪、下一步做什么、有什么坑、红线是什么"，并且文档不随项目长大而腐烂。**
> 方法论来源：`~/Doubao/skills/project-manager/` 的 execution-governance / execution-ops / templates-standards，本篇是其在本仓的实例；与 `AGENTS.md` 冲突时以 AGENTS 为准。

---

## 1. 单一真相源与沉淀收拢路由（讨论完，往哪放）

每种信息只有**一个**权威文件写"全量"，其他文件只放指针（DRY）。同一易变内容在两处写全 = 待收拢。

| 这类信息 | 唯一落点 | 规则 / 不要放哪 |
|---|---|---|
| 当前进度、下一步、阻塞、批次状态 | `03_进行中的任务/TASK_STATUS.md` | 唯一进度真相；**易变计数（下载多少、进度%、当天日期）只在这或数据状态文件**，他处只放指针 |
| 开放问题 / 已解决 / 做不通 | `03_进行中的任务/ISSUES.md` | 发现即记；验证过"做不通"的进 Won't Fix，避免重复踩 |
| 重要决策及理由（选了什么、否了什么） | `02_决策记录/` ADR | 只增不改；被取代只加"Superseded by #NN"演进注记 |
| 已聊清的需求、验收标准 | `docs/REQUIREMENTS.md` | 需求唯一文档，不与 BRD/旧稿并存；聊需求的动作走 `docs/需求讨论SOP.md` |
| 没聊清/待拍板的需求点 | `TASK_STATUS.md`「待拍板事项」 | 按需求讨论SOP §5 五种去向登记；`docs/待讨论需求清单.md` 已冻结为历史记录，不再新增 |
| 讨论过程、为什么这么走过来 | `docs/HANDOFF.md` §1（倒序日志） | 每轮重要讨论追加一条：聊什么→结论→为什么；它是过程不是结论 |
| 操盘手经验 / 每日复盘**原始素材** | `09_调研底稿与素材/操盘手经验/NNN_*.md` | 只读、不改原文；编号顺延 |
| 清洗后的操盘手结论 / 外脑档案 | `操盘手经验沉淀与需求输入.md`、外脑相关 docs | 必须带来源指针，不复制大段原文 |
| 策略规格 | `docs/strategies/*.md` | 参数、口径、已知偏差写清 |
| 数据口径、下了什么、多大 | `docs/数据资产清单.md` | 随某类下完/进度大跳立即更新 |
| 项目事实、工具坑、命令 | `AGENTS.md` §3 | 写稳定规则，不写易变进度 |
| 代码 / 配置 | `src/`、`scripts/`、`config/` | 脚本新增/删除要登记文档地图 |
| 定稿报告 / 方案 | `01_结论与产出/` | 只放定稿，不放草稿 |
| 大数据、原始数据、结果明细 | `data/`、`results/`（**gitignore 不入库**） | 人读小结可入 `01_`；明细 CSV 留本地 |
| 凭证、密钥、token | 环境变量 / `config/local_*`（gitignore） | **绝不入库、不进日志、不进对话** |

收拢三原则：① 过程件不污染持久文档；② 结论先有来源再写（区分 事实/一方称/假设）；③ 新增/删除/移动文档必须走 §3。

## 2. 维护节奏（什么时候做什么）

| 时机 | 必做动作 |
|---|---|
| 会话中随手 | 任务开始/子任务完成/完成/遇阻塞 → 立即改 TASK_STATUS；发现问题 → 立即记 ISSUES |
| 每轮重要讨论/决策收尾 | HANDOFF §1 倒序追加一条；需求聊清并入 REQUIREMENTS；重要选择记 ADR；操盘手新判断按 §1 归档 |
| 每次 `git commit` 前 | 过 §4 提交清单；跑 `scripts/doc_health_check.py`，**0 严重断链才提交** |
| 大任务完成后 / 每月 / 用户要求 | 跑完整体检（§5）；小问题当场修，结构性问题列方案先确认 |
| 关窗口 / 交接前 | TASK_STATUS、HANDOFF 更新到最新；跑体检；让新窗口按 `AGENTS.md §5` 冷启动并通过 §6 验收 |

## 3. 文档变更驱动矩阵（文档一变，自动触发，无需提醒）

| 变更 | 必做的联动动作 |
|---|---|
| 新增文档 | ① 先 grep 确认无同类文档；② 更新 `docs/DOCUMENTATION_MAP.md`；③ 需要建新目录则同步 `docs/DIRECTORY_STRUCTURE.md` 与 `.gitignore`；④ 在父文档加链接；⑤ 重要架构决策评估补 ADR |
| 删除文档 | ① 全仓 grep 文档名找全部引用（含 markdown 链接、反引号路径、目录树三种形态）；② 改/删引用；③ 更新 MAP/STRUCTURE；④ 删空目录；⑤ 持久文档删除先确认职责有承接方 |
| 移动/改名 | 等同删除+新增：重算跨目录相对链接（`../` 层数）、更新全部引用/MAP/STRUCTURE，全仓 grep 旧名 0 残留 |
| 调整目录结构 | 先出方案（前后结构+移动清单+引用更新清单）→ 执行 → 全量更新 → 复扫；重大调整记 ADR |
| 优化/合并内容 | 内容搬走后原文改链接；同步他处引用；合并/拆分属结构变更，评估 ADR |

## 4. 提交前检查清单

- [ ] 无密钥/token/敏感信息；`data/`、`results/` 大文件未入库（`git status` 核对）
- [ ] TASK_STATUS 已更新到当前进度；新决策已入 ADR；本轮重要讨论已追加 HANDOFF §1
- [ ] 新增/删除/移动文档已按 §3 更新 MAP / STRUCTURE / 引用，**0 真实断链**
- [ ] 新增/删除脚本已登记文档地图"工具清单"，参数变更已进对应 SOP
- [ ] 本轮需求讨论已按 `docs/需求讨论SOP.md` 收口（结论落 REQUIREMENTS / 台账 / 待拍板 / 挂起，未只留在聊天里）
- [ ] 易变计数只在台账/状态文件，他处没有写死第二份
- [ ] `09/` 原始素材未被修改；跑过 `scripts/doc_health_check.py` 无 ERROR

## 5. 文档健康度体检

### 5.1 自动项 —— `scripts/doc_health_check.py`（仓库根运行）

```bash
.venv/bin/python scripts/doc_health_check.py        # 或 python3
```

检查：核心文件齐备、markdown 相对链接与正文路径式引用断链、空目录、冷启动链逐跳可达、入库文档在 MAP 的登记覆盖、`data/results/凭证` 是否误入 git、"待创建/待补充/TODO" 残留占位。有 ERROR 退出码非 0。

### 5.2 人工项（脚本查不了，大任务后/每月过一遍）

- **重叠**：建"主题 × 文档"矩阵，每个主题唯一权威源，其余改链接（重点查：项目目标、目录树、存储分工、路线图/待办、常用命令、数据口径）。
- **篇幅**：无 >500 行且跨领域的文档，该拆就拆。
- **废话**：删"正确的废话"、AI 套话、空章节；每段要有独立信息增量。
- **一致性**：术语/口径/命令/路径/参数在 AGENTS↔各 SOP↔脚本间同一说法；核心文档与真实现状一致（如"待创建"但文件其实已存在=过时）。
- **记忆 bundle**（如启用）：index 登记的 concept 都真实存在、只放结论+指针、无易变状态、来源链接可达。

### 5.3 问题分级

- 小问题（断链、过时数字、漏登记、错字、过时状态）→ **当场修**。
- 结构性/拿不准（目录改名、文档拆分、流程变更）→ 列方案先确认（L1/L2），不擅自大改。
- 用户要求"只读体检"→ 一律不改，只出报告（报告默认落 `data/_workspace/`，不入库）。
- 改后用不同方式复扫确认无回退。

## 6. 冷启动验收（"只给仓库路径"测试）

新窗口只拿到仓库路径、按 `AGENTS.md §5` 读完规定文档后，**不翻旧对话**，必须能用大白话回答 6 个问题：

1. 这项目是什么、为谁做、**量子系统 / 外脑两条主线**分别是什么？
2. 现在在哪个阶段/门（G1/G2/G3）？最近完成了什么？
3. 下一步做什么？有哪几个待拍板选项、各自代价、推荐哪个？
4. 有哪些开放问题、坑、数据缺口（ISSUES）？
5. 红线是什么？（不自动下单、不承诺收益、不替操盘手定参数、数据/凭证不入库、原始素材只读）
6. 关键命令去哪查 / 怎么跑？（venv、扫描器、回测、下载进度、文档体检）

**验收方法**：新窗口动手前先口头复述这 6 问；答不上来、或答案在不同文档里互相矛盾，即判冷启动不合格，按 §5 修好对应文档再开工。这一条就是"只通过仓库就能知道情况及要做什么"的验收标准。
