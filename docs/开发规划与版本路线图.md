## 0. 一句话结论：定 3 样东西就能开工，数值不用先谈清

系统执行（写代码）**不需要**等所有买卖阈值谈清楚——阈值全部参数化、先给工作默认值、T30 校准时只改参数不动架构。
真正要先"冻结一版"的只有 3 个**结构性决策（开工三闸门）**，且我都能先起草、你和操盘手只做"对不对"的判断：

1. **三策略规则结构**：003 是哪六层、哪些一票否决；001/002 的进出场状态机；001 与 002 出独立信号还是合并评级。
2. **扫描器 v2 的 MVP 范围切一刀**：第一版端到端包含哪些规则、明确不包含哪些（数据没就绪的推后）。
3. **模拟盘每日工作流一版**：几点跑、产出什么、人看什么、怎么记买卖与复盘（D-11）。

> 需求分层说明（回应"技术数值为何出现在需求里"）：**业务需求**只讲"要达成什么效果"（如"突破后要确认站稳，避免单日假突破"）；
> 95% 覆盖率、≤30 分钟、误差容差这类是**非功能需求（技术验收门槛）**，归 REQUIREMENTS 非功能节与 ADR，不混进业务规则。
> 规格里每条业务规则都与它的技术阈值分开写：阈值集中在参数表、统一标注 `[假设·待T30]`。

## 2. 开工三闸门（M0 内冻结）

### 闸门 1 · 三策略可计算规则结构（001/002/003）

冻结"规则与状态机"，**不冻结数值**。产出《001/002/003 策略可计算规格 v0.1》，每条规则四要素：业务原话 → 所需字段 → 计算逻辑 → 参数（默认值 + `[假设·待T30]`）。

- **003 六层价值过滤（前置门槛，不通过不进 001/002）**：定"哪六层 + 每层是一票否决还是打分"。硬拦截至少含 ST、业绩雷（净利润大幅下滑/现金流恶化）、商誉减值风险；其中 ST 本地日线有 `isST`，业绩用 profit/growth，**商誉/流通市值 baostock 日线没有 → 列数据缺口（T31），先留接口标"待确认"，不伪造**。
- **001 左侧状态机**：地量 → 放量试盘（间歇放量阳线）→ 缩量回踩**不破前低** → 连续不创新低 → 再放量确认 → 入场；对称定义出场。
- **002 右侧状态机**：长期横盘/均线粘合前提 → 缩量十字星变盘 → 放量突破箱体上沿 → **站稳 N 日不跌回**（排除假突破）→ 入场；对称定义出场。
- **出场规则系统化**：止损（工作假设 -7%）、最长持有（工作假设 10–20 日，操盘手为波段、可能更长，待 T30）、目标/信号离场；进出场必须对称（借鉴 tickflow 契约）。
- **信号产出形态**：001、002 各自独立标签（建议，便于分别校准胜率），003 作共同前置。
- 参数默认值全部来自操盘手原话（经验127/128：地量<20日均量70%、试盘≥120%、突破≥130%、站稳2–3日、流通市值<200亿、板块涨停≥5家）与 tickflow 候选，**只作工作假设、AI 不替操盘手定参**。

### 闸门 2 · 扫描器 v2 的 MVP 范围切一刀

按"数据是否就绪、是否依赖操盘手精调"分三档，第一版只承诺 v2.0：

| 版本 | 内容 | 依赖 |
|---|---|---|
| **v2.0（A 类·先做）** | 声明式策略骨架（每策略一文件：参数集中/warmup 防未来函数/纯函数 compute/进出场对称）；003 中**本地数据可算**的硬门槛（isST、业绩同比、现金流）；001/002 完整时序状态机；Polars 全市场扫描 + 信号报告；用经验127/128 正负样本回放验证**结构**（如中石科技式单日假突破必须被排除） | 仅闸门 1 + 已下载 Parquet（先 2116 只，下完重跑） |
| **v2.1（B 类·校准）** | T30 后阈值定稿、3 号池成分 64 vs 53 对齐（I8）、参数敏感性 | 操盘手 T30 |
| **v2.2（C 类·补数）** | 板块共振（涨停≥5家）、资金流、商誉、流通市值、全市场财务 | T31 数据 |

### 闸门 3 · 模拟盘每日工作流（D-11）

冻结"一天怎么运转"，我先起草默认（对标操盘手 15:05 四段式 + 本仓 18:30 盘后编排）：盘后自动补数 → 跑量子调仓信号 + 外脑 001/002/003 扫描 → 产出当日报告（行情/持仓/信号/事件/待人工确认项）→ 人工确认、次日开盘成交、记账、复盘留痕。定"13:30/15:05/18:30 各时点做什么、报告字段、复盘模板"。

## 4. 并行时序与关键路径

- **后台贯穿（不挡前台开发）**：T13 全市场下载（约 4–6 个开机日，合盖暂停、断点续传）→ 下完跑 T34 重转 Parquet + T35 增量直写。M1 先用已下的 2116 只开发，下完重跑基准与扫描。
- **前台关键路径**：M0（三闸门）→ M1（v2.0 代码）→ M2（T30 校准是必经人工节点）→ M3（时间验证）。
- **可并行**：T31/T32 数据工程与 M1 并行（baostock 财务补数避开下载高峰）；复盘模板、D-11 在 M0 内并行。
- **关键人工节点只有一个**：操盘手 T30。口径我已收口（I7），他只需导出数值与样本判定，越早约越省等待。
